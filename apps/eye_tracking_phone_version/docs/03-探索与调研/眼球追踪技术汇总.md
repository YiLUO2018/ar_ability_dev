# 1. 问题索引与结论速查

## 第一轮：眼镜式眼球追踪目标与方案调研

**问题：** 在眼镜上装一个朝向眼睛的摄像头，做眼球/眼神追踪，给出设计方案，并调研 GitHub 和 arXiv 上类似方案。

**核心结论：**
- 硬件布局四类：镜框上方/鼻托直接朝眼；镜腿 + 波导/热镜折转光路；镜框下方 + 反射镜；传感器嵌入镜片。
- 关键器件：近红外摄像头、850 nm 红外 LED、低功耗 MCU 或神经形态芯片。
- 商用：Pupil Labs Invisible/Neon、Tobii Pro Glasses 3、AdHawk MindLink、Viewpointsystem VPS Next。
- 开源：Pupil Labs Pupil、MEYELens、WearableEyeTracker、TerminatorGlasses、EyeTrackVR/OpenIris、FIXEIN。
- arXiv：FlatTrack 无透镜摄像头、事件相机亚毫秒追踪、GazeTrak 声学追踪、mmET 毫米波雷达、JaneEye 事件追踪加速器。
- 推荐路线：原型验证 → 集成优化 → 算法与功耗优化。

## 第二轮：个人开发者手机近距离拍摄眼球做算法原型

**问题：** 个人开发者，关注视觉算法，想用手机近距离拍摄眼球，先做算法原型。

**核心结论：**
- 拍摄：镜头距眼 5–15 cm，手动对焦锁定，间接强光，保持稳定，1080p 60fps 或 4K 30fps。
- 方案：后置摄像头 + 镜子，或前置 + 外接微距镜头。
- 算法：传统瞳孔/虹膜检测 → 几何映射；端到端 CNN 回归；混合 MediaPipe/PFLD + 几何。
- 数据集：InvisibleEye、TEyeD、OpenEDS、GazeCapture。
- 工具：JEOresearch/EyeTracker、PyPupilEXT、pupil-labs/pupil、L2CS-Net、MobGazeNet、GazeTorch、EyeTheia、MediaPipe Face Mesh。
- 顺序：先传统跑通，再端到端迁移。

## 第三轮：如何根据瞳孔推断注视方向？理论基础是什么？

**核心结论：**
- 眼球近似球体，绕固定旋转中心转动，瞳孔中心沿球面移动。
- 3D 瞳孔中心经透视投影到 2D 图像，映射非线性：
  \[
  u \approx f \cdot \frac{R\sin\theta}{D-R\cos\theta}
  \]
- 单瞳孔受头动、摄像头位移、瞳孔缩放、眼睑遮挡、个体差异影响，必须校准。
- PCCR：引入角膜反射点，P-CR 向量对头动不敏感。
- 校准建立图像特征 → 注视方向映射。
- 光轴与视轴有约 5° kappa 角，校准自动补偿。
- 流程：采集 → 瞳孔检测 → glint 检测 → 特征提取 → 映射 → 后处理。

## 第四轮：五个基础深入问题

1. **眼球绕点旋转还是绕轴旋转？**
   物理上绕旋转中心点；数学上绕点旋转可等价为绕瞬时轴。建模简化为刚性球体绕固定点旋转。

2. **距离固定时，3D 瞳孔到 2D 图像映射能否数学推导？**
   理想条件下可解析推导；实际因角膜折射、瞳孔椭圆化、个体参数未知、镜头畸变，用校准拟合。

3. **参考点消歧、角膜反射点、PCR 向量是什么？**
   参考点消歧：用 glint 消除“瞳孔移动源于眼动还是头动”的歧义。
   角膜反射点：红外光源在角膜表面形成的虚像。
   P-CR 向量：瞳孔中心减角膜反射点，对头动不敏感。

4. **校准能通过眼球动作标定吗？**
   可以，叫隐式/自动校准。利用扫视、平滑追踪、多模态、自监督。通常需初始粗略校准。

5. **光轴、视轴、kappa 角是什么？**
   光轴：眼球光学系统对称轴。
   视轴：中央凹到注视点连线，真正看的方向。
   kappa 角：两者夹角，平均约 5°，因人而异 0–8°。

## 第五轮：五个进阶问题

1. **考虑眼球在眼窝内平移量怎么做？**
   平移向量作为模型参数联合优化；6-DoF 眼球追踪；解剖学约束；LeGrand 眼球模型。手机原型可先在 3D 模型加 3 维平移参数。

2. **校准方式有哪些？**
   显式多点、显式单点、隐式/自动、免校准。建议显式 9 点起步，再隐式校准。

3. **瞳孔形状变化能否区分眼动和头动？**
   眼动 → 圆变椭圆，宽高比 \(\delta=\cos\theta\)；头动平移 → 形状不变；头旋转也会椭圆化。应作为辅助特征，与瞳孔中心、glint 联合。

4. **角膜反射点光源实际怎么实现？**
   常用 850 nm 近红外 LED，也可 VCSEL、激光二极管。眼镜可放鼻托、镜框上缘、镜腿；屏幕可四角布置。手机原型：镜头旁贴 850 nm IR LED + 窄带滤光片，或先用屏幕反射。

5. **整个眼球追踪能否端到端实现？**
   可以，是当前主流方向。路线：纯外观端到端、解剖学约束端到端、无 glint 端到端、屏幕内容感知。优势是简化 pipeline、鲁棒、可 glint-free；挑战是数据、泛化、可解释性。

## 第六轮：显式校准 + 隐式校准策略

**问题：** 首次显式校准，后续基于初值持续隐式校准，解决累积误差，是否可以？有更好方式吗？

**核心结论：**
- 可行，且是业界主流方案。
- 隐式方法：UI 点击回溯、光标代理、领域高置信时刻、RLS 在线更新。
- 更优：无训练隐式校准、训练漂移修正器、多模态融合校准。
- 关键数据：眼镜滑动 0.1 mm ≈ 1° 注视误差。
- 需漂移检测与重校准触发，如累积漂移 > 2.0° 时提示快速显式校准。
- 建议：先 9 点显式，再 UI 点击隐式 + RLS。

## 第七轮：要点整理与开发路线

**问题：** 整理要点，详细内容发出来；打算先用传统算法，再用端到端算法。

**核心结论：**
- 输出完整文档：硬件、调研、理论、校准、算法、手机原型、开发阶段。
- 开发路线：数据采集 → 传统算法跑通 → 隐式校准集成 → 端到端模型尝试 → 端上部署验证。
- 挑战：隐私、佩戴滑动、功耗散热、个体差异、端到端泛化。

# 2. 项目目标与硬件设计方案

## 2.1 目标定义与核心约束

在眼镜形态下集成朝向眼睛的摄像头，实现眼球/眼神追踪。核心约束：

- 微型化：镜框空间有限。
- 低功耗：电池供电持续运行。
- 不遮挡视线：光学元件对可见光透明。
- 佩戴稳定：头部运动带来滑动问题。
- 实时性：低延迟输出注视方向。

## 2.2 摄像头布局方案

### 方案 A：镜框上方/鼻托附近直接朝向眼睛

将微型红外摄像头安装在镜框上缘或鼻托区域，直接朝内拍摄眼睛。Apple 专利方案即在鼻托附近设小平台放置摄像头，正对眼睛。结构简单，但需避免遮挡视线。

### 方案 B：镜腿 + 光学波导/反射镜折转光路

摄像头放在镜腿等空间充裕位置，通过嵌入镜片中的反射式波导或热镜将眼睛图像引导至摄像头。专利 US20260153732A1 提出嵌入式波导：镜片中嵌入曲面热镜，反射红外光同时透射可见光，红外摄像头置于镜腿。美观性好、位置灵活，但光学设计复杂。

### 方案 C：镜框下方/下方镜片边缘

早期专利 EP2499961A1 中，眼摄像头安装于眼睛前上方，配合前下方反射镜形成光路。反射镜可为平面镜、球面镜或热镜，球面镜可扩大视场。

### 方案 D：眼动追踪传感器嵌入镜片

Tobii Glasses 3 将 16 个红外光源和 4 部眼动追踪传感器嵌入镜片，支持位置调整且不遮挡视野。集成度最高。

## 2.3 关键器件选型

- **摄像头：** 近红外摄像头，典型 192×192 @200 Hz。豪威 OC0TC1B-RAVA 专为眼动追踪设计。极致轻薄可考虑无透镜摄像头，如 FlatTrack。
- **红外光源：** 850 nm 红外 LED，增加瞳孔与虹膜对比度并产生角膜反射。
- **处理器：** 低功耗 MCU（nRF52840）、神经形态芯片（Speck2f）、STM32N6 带 Neural-ART 加速器。

## 2.4 光学设计要点

- 使用热镜在可见光透明、红外高反射，解耦红外光路与视线。
- 眼摄像头 FOV 覆盖眼球活动范围，无需覆盖全部视野。
- 近距离拍摄需短焦微型镜头或计算畸变校正。

# 4. 眼球追踪理论基础

## 4.1 眼球运动学

眼球近似为球体，绕一个固定旋转中心转动，位于角膜顶点后方约 13–15 mm。可向任意方向转动。数学上任何绕点旋转可等价为绕某根瞬时轴旋转。建模简化为刚性球体绕固定点旋转，平移量约 1–2 mm。

## 4.2 3D 到 2D 投影

瞳孔中心位于虹膜平面，距旋转中心约 10–12 mm。眼球旋转 \((\theta_x,\theta_y)\) 时，瞳孔中心空间坐标变化，经透视投影到图像：

\[
u \approx f \cdot \frac{R \sin\theta}{D - R \cos\theta}
\]

图像位移与注视角度非线性。实际中因角膜折射、个体参数未知、镜头畸变，不解析求解，而用校准拟合。

## 4.3 单瞳孔方法的局限

瞳孔图像位置同时受头动、摄像头位移、瞳孔大小变化、眼睑遮挡、个体差异影响。单瞳孔必须严格校准，仅适用于头部和摄像头相对固定场景。

## 4.4 角膜反射与 PCCR 方法

- **角膜反射点（glint）**：红外光源在角膜表面形成的虚像，相对眼球位置基本固定。
- **P-CR 向量**：瞳孔中心减角膜反射点。头动时两者同移，差值不变；眼动时瞳孔移动大、glint 移动小，差值变化显著。因此对头动不敏感，能鲁棒反映眼球旋转。
- **参考点消歧**：用 glint 作为参考，消除“瞳孔移动源于眼动还是头动”的歧义。

## 4.5 光轴、视轴与 kappa 角

- **光轴**：眼球光学系统对称轴，穿过角膜顶点、晶状体中心、后极。
- **视轴**：中央凹到注视点的连线，代表真正看的方向。
- **kappa 角**：光轴与视轴夹角，平均约 5°，因人而异 0–8°。眼动追踪测量几何朝向，需校准补偿到视轴。

## 4.6 瞳孔形状变化

眼球转动时瞳孔投影从正圆变椭圆，宽高比 \(\delta = \cos(\theta)\)。头动平移时形状不变。但头部旋转也会导致椭圆化，角膜折射、瞳孔缩放、分辨率限制均影响判断。应作为辅助特征，与瞳孔中心、glint 联合使用。

# 5. 校准方法

## 5.1 显式校准

- **多点校准**：9 点或更多，最常用。3D 几何单摄像头至少需 5 点求解眼球参数。
- **单点校准**：需先验知识或用户数据库。

## 5.2 隐式/自动校准

利用自然交互行为在后台持续校准：

- **基于 UI 交互**：点击按钮时假设注视点在 UI 元素，回溯点击前注视轨迹。Online-EYE 隐式平均误差 1.94°，显式 1.19°，通用 3.08%。
- **基于光标操作**：鼠标/触摸光标位置作为注视代理。COMETIC 误差降低 27.2%。
- **领域特定高置信度时刻**：如手术中工具与组织接触点。SurgGaze 误差降低 40.6%。
- **算法更新**：递归最小二乘法（RLS）在线更新校准矩阵。

## 5.3 免校准

依赖大规模预训练深度学习模型，将校准信息编码在网络权重中，精度通常低于个性化校准。

## 5.4 推荐策略

**首次显式校准 + 后续隐式校准**是主流且稳健的方案。显式校准获得高精度初值，隐式校准持续修正佩戴滑动累积误差。眼镜在鼻梁上仅 0.1 mm 滑动可导致约 1° 注视误差。可进一步引入无训练隐式校准、训练漂移修正器、多模态融合校准。需设计漂移检测与重校准触发机制，如累积漂移 > 2.0° 时提示快速显式校准。

# 6. 算法路线：传统与端到端

## 6.1 传统算法路线

**瞳孔/虹膜检测 → 几何映射**

- **瞳孔检测：**
  - 阈值 + 轮廓法：快速，对光照敏感。
  - Starburst：射线寻找边缘点拟合椭圆，对遮挡鲁棒。
  - Swirski2D、ExCuSe、ElSe、PuRe：经典算法，PyPupilEXT 集成多种。
- **虹膜检测：** OpenCV HoughCircles 或瞳孔周边搜索。
- **注视映射：** 多项式回归或小型神经网络，输入瞳孔相对坐标或 P-CR 向量，输出注视角度。

## 6.2 端到端深度学习路线

- **纯外观端到端**：CNN 直接从眼球图像回归注视向量。MobileNetV1 等轻量骨干可达 >100 FPS，约 2.61° 误差。
- **解剖学约束端到端**：显式加入几何约束，TEyeD 上平均角误差 2.004°。
- **无 glint 端到端**：摆脱红外光源，未见被试上平均角误差 1.53°。
- **屏幕内容感知**：HiFiGaze 利用屏幕反射，iPhone 上单次推理 0.78 ms。

**优势：** 简化 pipeline，对噪声和遮挡鲁棒，可 glint-free。
**挑战：** 需大量数据，跨被试泛化需微调，可解释性差。

## 6.3 传统 vs 端到端

| 路线 | 优势 | 劣势 | 适用 |
|------|------|------|------|
| 传统几何 + PCCR | 可解释、可调试、数据需求低 | 对遮挡和滑动敏感，pipeline 长 | 原型、教学、低数据场景 |
| 端到端外观 | 简化、鲁棒、可 glint-free | 数据需求大、泛化挑战 | 产品化、数据充足 |
| 混合 | 兼顾可解释与鲁棒 | 设计复杂 | 工程折衷 |

# 7. 手机近距离拍摄原型开发

## 7.1 拍摄条件

- 镜头距眼睛 5–15 cm。
- 手动对焦锁定，关闭美颜/人像滤镜。
- 间接强光，避免大面积高光遮挡瞳孔。
- 固定稳定，1080p 60fps 或 4K 30fps。
- 同步记录注视目标位置，用于 gaze 标注。

## 7.2 实用方案

- 后置摄像头 + 镜子：利用后置画质和对焦，屏幕面向自己调整角度。
- 前置摄像头 + 外接微距镜头：成本低，画质受限。

## 7.3 数据集

- **InvisibleEye**：28 万+ 近距离眼图，带 gaze 标注，强烈推荐。
- **TEyeD**：2000 万+ 眼图，2D/3D 分割、landmark、gaze。
- **OpenEDS**：Meta 近红外眼图，像素级分割。
- **GazeCapture**：250 万帧手机端眼动，1450+ 参与者。

## 7.4 开源工具

- **瞳孔检测：** JEOresearch/EyeTracker、InfraredPupilTracker、PyPupilEXT、pupil-labs/pupil。
- **注视估计：** L2CS-Net、MobGazeNet、GazeTorch、EyeTheia。
- **快速原型：** MediaPipe Face Mesh、GazeTracking。

# 8. 开发路线建议：传统算法 → 端到端算法

## 阶段一：数据采集与标注（1–2 周）

用手机拍摄 5–10 段眼球视频，覆盖不同注视方向、光照。用 JEOresearch/EyeTracker 或 PyPupilEXT 跑瞳孔检测，观察效果，调整拍摄条件。

## 阶段二：传统算法跑通（2–4 周）

实现瞳孔检测 + 椭圆拟合 + 多项式校准。先用 9 点显式校准，验证头部固定下的精度。引入 P-CR 向量（若加红外光源）提升头动鲁棒性。用 RLS 做在线更新。

## 阶段三：隐式校准集成（2–4 周）

基于 UI 点击事件回溯注视轨迹，过滤可靠数据，持续更新校准模型。监控漂移，设置重校准触发。

## 阶段四：端到端模型尝试（4–6 周）

从 L2CS-Net 或 GazeTorch 等轻量模型开始，用 InvisibleEye/GazeCapture 预训练权重迁移。尝试纯外观端到端 + 无 glint 方案，直接用手机采集图像训练小型 CNN 回归注视角度。对比传统与端到端精度、鲁棒性、速度。

## 阶段五：端上部署验证（可选）

转 TFLite/LiteRT，在 Android 上跑实时推理。参考 L2CS-Net Android 部署示例。

# 9. 关键挑战与应对

- **隐私：** 朝向眼睛的摄像头持续采集生物特征，需本地处理与加密。
- **佩戴滑动：** 0.1 mm 滑动 → 1° 误差，靠隐式校准持续补偿。
- **功耗与散热：** 事件相机、MEMS 路线功耗优势明显，但生态不成熟。
- **个体差异：** kappa 角、眼球半径、瞳孔位置不同，校准自动补偿。
- **端到端泛化：** 跨被试精度下降，需个性化微调或隐式校准。
- **隐式校准数据质量：** 需时空过滤，确保“注视-目标”数据可靠。
- **漂移检测：** 累积漂移超过阈值时触发重校准。

# 10. 全讨论一句话总览

- **硬件：** 眼镜朝眼摄像头 + 红外光源，PCCR 或端到端路线。
- **理论：** 眼球绕固定点旋转，3D→2D 非线性投影，校准是桥梁。
- **算法：** 传统可解释、易起步；端到端简化、鲁棒、可 glint-free。
- **校准：** 显式初值 + 隐式持续修正，解决佩戴漂移。
- **开发：** 手机近距离拍摄做原型，先用传统算法，再转端到端，配合 InvisibleEye/GazeCapture 和开源工具迭代。
- **最终建议：** 先实现 9 点显式校准 + 瞳孔检测 + 多项式映射；再引入 UI 点击隐式校准 + RLS；最后尝试 L2CS-Net/GazeTorch 等端到端模型，并考虑无 glint 方案。
