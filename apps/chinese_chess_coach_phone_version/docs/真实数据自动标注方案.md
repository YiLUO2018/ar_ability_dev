# 真实数据自动标注方案（阶段 1.5）

**日期**：2026-10-02（方案）；2026-10-05/06（实施）
**状态**：已实施（M0–M5 落地，YOLO 学生模型已训练，见 §11 实施结果）
**定位**：细化 `方案v2` 第 4.4 节「真实照片半自动标注」，解决合成→真实域差——用**无监督/零样本 + 几何先验**为主、人工抽检兜底的方式，给真实帧自动打标，再混合微调。

---

## 1. 目标与原则

1. **少人工**：真实帧的伪标签尽量自动生成，人工只做「低置信兜底 + 抽检」，不做逐张全标。
2. **不用「模型自己给自己打标」**：避免自举退化（echo chamber）。伪标签来源必须与待训练的模型**解耦**（几何 / 分割 / 时序 / 合法性），或有人工闸门。
3. **分两类任务，策略不同**：
   - **棋盘角点**：靠几何（直线交点 + 单应 + 直角/宽高比），可做到亚像素。
   - **棋子类别**：靠时序投票 + 象棋合法性 + 引擎校验，可做到接近全自动。
4. **保持混合训练**：真实数据与合成数据一起微调，不让真实小样本淹没合成多样性。

## 2. 方法总览

| 方法 | 针对 | 监督性质 | 精度 | 定位 |
| :-- | :-- | :-- | :-- | :-- |
| A. 分割粗定位（SAM / MobileSAM / SAM2） | 角点（粗） | 零样本（SA-1B 预训练） | 掩码级（几~几十 px） | 粗定位 + 缩小搜索 ROI |
| B. 网格几何精修（单应 + 直角 + 宽高比 + 交比 + 重投影） | 角点（精） | 无监督（纯几何） | 亚像素 | **角点伪标签主来源** |
| C. 时序投票 + 合法性 + 引擎校验 | 棋子类别 | 无监督（结构先验） | 接近 100%（投票后） | 棋子伪标签主来源 |

> 关键：角点的**精确值**只能来自几何（两条直线交点），而不是语义（分割掩码 / 热力图）。分割与热力图回答「棋盘大概在哪」，几何回答「角点精确在哪」。

## 3. 方法 A：分割粗定位（SAM）

**思路**：SAM 对「桌面上的平面棋盘」这种前景/背景分离很擅长，可稳定给出棋盘区域掩码；从掩码拟合同四边形得到粗四角。

**局限（决定了它只能做粗定位）**：
1. 掩码边缘「糊」、角点「圆钝」，拟合四边形误差几~几十 px。
2. 掩码给的是**物理棋盘边**，而角点模型学的是**最外层网格线交点**（canonical 里网格外留 25px 边框），两者有系统偏差。
3. 模型大（ViT-B 375MB / ViT-H 2.5GB），但离线标注无所谓；端上可选 MobileSAM/EdgeSAM（~40MB）。

**用法**：SAM/MobileSAM 输出棋盘掩码 → 缩小 ROI → 交给方法 B 在 ROI 内做直线检测与精修。SAM2（视频）还可跨帧跟踪掩码以抗抖。

**资源**：`L:\Reinforcement_Learning\segment\segment-anything-main`
- 权重：`models/sam_vit_b_01ec64.pth`（375MB）、`sam_vit_l_0b3195.pth`（1.2GB）、`sam_vit_h_4b8939.pth`（2.5GB）
- 包：`segment_anything/`（`sam_model_registry` + `SamPredictor` / `SamAutomaticMaskGenerator`）

## 4. 方法 B：网格几何精修（核心）

把棋盘当成一块**自标定平面标定板**（张正友标定法那套机器）。

### 4.1 核心等价关系
4 角 ↔ 单应 H，是同一个 8 自由度（DLT）。所以「几何约束校正角点」=「几何约束校正 H」。

### 4.2 可用几何约束（由弱到强）

| 约束 | 含义 |
| :-- | :-- |
| 单应唯一性 | 4 组点对应确定 H（8 DoF） |
| **直角/正交** | 网格在 3D 正交；用正确 H 校正后横竖线应互相垂直（消失点 VP_h ⊥ VP_v 满足正交约束）。H 错 → 校正结果被剪切 |
| **宽高比** | 网格 8 格宽 × 9 格高 = 8:9；正确 H 校正后宽高比应为 8:9（消尺度歧义） |
| **交比不变** | 每条线上 9/10 个交点在 3D 等距；透视下交比不变（等距四点交比恒 = 4/3） |
| **重投影误差** | 检测到的网格交点用 H 投回 canonical，量到已知网格节点的像素距离，最小化它（真正优化目标） |

> 优雅之处：把检测到的交点拟合到 **canonical 网格** 时，直角 + 宽高比 + 等距这些约束被**隐式**满足——canonical 节点本身正交、8:9、等距。当检测点足够多（≥10），重投影最小化就等价于施加了全部几何先验；点少时才需要显式加正交/宽高比正则。

### 4.3 管线

```
检测直线（LSD/Hough）→ 候选网格交点
        ↓
粗提议 4 角（SAM 粗定位 / 角点模型 / 线极值）
        ↓
H = DLT(4角)；再迭代优化 H（等价于优化 4 角）
    目标 = 重投影误差 + λ·(正交违规 + 宽高比违规)
        ↓
输出：精修后 4 角 + H + 重投影评分（像素级质量分）
```

实现要点：
- **交点检测**：LSD 线段 → 分水平/垂直两族 → 求「水平×垂直」交点 → 聚类（一个真实网格节点有多组线对交于同点）。
- **匹配（ICP 思路）**：用候选 H 把 90 个 canonical 节点投回图像，对检测交点做最近邻匹配，RANSAC 重拟合，迭代。
- **优化**：Levenberg-Marquardt / `cv2.findHomography(RANSAC)` 迭代即可，重投影误差为像素级。
- **质检分数**：inlier 重投影误差就是「这帧检测好不好」的客观度量。

### 4.4 质量分 → 伪标签接受标准
- 重投影误差 < 2px（且正交/宽高比偏差小）→ 直接当角点伪标签。
- 2~5px → 候选，人工微调（点击 4 角）。
- > 5px → 丢弃或人工重标。

## 5. 方法 C：棋子时序投票 + 合法性校验

真实对局中盘面多帧不变，可用结构先验自动打标：

1. **时序投票**：同一局面连续 N 帧跑分类模型，每交叉点多数投票，单帧错 3 子→几十帧后基本清零。
2. **合法性校验**：结果必须满足数量约束（每方将 1、仕/相/马/车/炮 ≤2、兵 ≤5）、将帅不照面；不合法→回退人工。
3. **引擎复核**：`KotlinChessEngine` 判合法性，甚至校验局面是否可达。
4. **人工抽检**：只对低置信/不合法/与邻居不一致的帧人工过一遍。

## 9. 方法 D：运动功能监督 + 标准开局引导（2026-10-04 新增）

> 本节是「运动 → 身份」方案的完整落地边界，与上文方法 C（时序投票）互补：方法 C 依赖已有分类器做投票纠错（有自举退化风险，见原则 2），方法 D 从零开始、用「运动 + 开局」这种与待训练模型**解耦**的监督信号给棋子打标。

### 9.1 核心思想：身份 = 走法规则（转移函数）

每种子力的身份本质是其**走法规则**——给定（位置 + 盘面占位 + 走子方），允许走哪些格。这是一台状态机/转移函数，且 7 种走法规则两两不同。因此从「状态 → 动作」的转移样本出发做**系统辨识**，理论上可以认出这台机器（棋子类型）。

### 9.2 运动辨识的三个前提 + 一个硬边界

| 项 | 内容 | 结论 |
| :-- | :-- | :-- |
| ① 类型可辨识 | 帅/仕/相/马/车/炮/兵走法规则两两不同 | ✅ 理论上可分出 7 类 |
| ② 占位信号 | 区分「炮隔子吃 vs 车直接吃」需要知道「哪格有子」（占位），不是身份 | 分割即可给，比身份便宜 |
| ③ 稀有行为覆盖 | 车 vs 炮只在「吃子」时刻不同；马靠「蹩马腿」；帅靠「飞将」 | 「样本量足够」= 覆盖稀有行为，≠ 帧数多 |
| ④ 硬边界：运动色盲 | 红车/黑车走法完全相同，红黑永远无法用运动区分 | ❌ 运动最多 7 类，颜色必须外观（HSV）另解 |

**关键结论**：运动负责「是什么子」（7 类），外观负责「是哪方」（红/黑），拼起来才是完整 14 类。运动推断身份的极限是 7 类，不是 14 类。

### 9.3 身份的两个来源（分时复用，非同时）

| 场景 | 身份来源 | 运动的作用 |
| :-- | :-- | :-- |
| 先验已知（标准开局 / 传播中） | 开局地图 + 规则 forward 传播 | 只做 from→to，**更新**身份 |
| 先验未知（中途冷启动 / 传播断链） | 运动推断（7 类）+ 外观分色 | **重建**身份，软约束 / 重同步 |

> 二者分时复用：身份已知时运动只更新状态；身份丢失时运动才推断身份。不是「已知了还推断」的循环。

### 9.4 标准开局引导（bootstrap 种子）

标准开局 32 子位置**完全确定**，直接给出完整的 14 类标签（含颜色）——零成本的终极种子。

**流程**：视频第 0 帧检测标准开局 → 用开局地图赋值全部 32 子身份 → 之后每帧用 from→to + 规则 forward 传播更新身份 → 传播断链时回到「运动推断 7 类 + 外观分色」重同步。

### 9.5 如何自动识别标准开局：占位匹配

不认字、不分类，只判断「每个交叉点有没有棋子」（占位），与标准开局占位掩码比对。

**步骤**：
1. SAM 已给出棋盘单应 H（~3–4px）。
2. 把帧 warp 到 canonical 棋盘，得到 90 个交叉点。
3. 对每个交叉点做**二分类「有子/无子」**（前景 blob / 颜色区别于棋盘底 / 圆形边缘），无需区分是车是炮。
4. 得到 90bit 占位向量，与标准开局掩码比对。

**标准开局占位掩码**（32 子）：
- 底线两排（rank 0 / rank 9）：9 子全满
- 炮两排（rank 2 / rank 7）：只有第 1、7 列有子
- 兵两排（rank 3 / rank 6）：只有第 0、2、4、6、8 列有子
- 中间 rank 4/5（河界区）：全空

**为什么可靠**：该掩码高度独特（对称、满底排、炮在固定列、兵在偶数列、中间全空），随机中局恰好相同概率≈0；且占位二分类远比 14 类分类容易，还可利用「32 子 + 对称」强先验。

**容差与时机**：
- 只在视频**第 0 帧**（走子前）检测；一旦走了 1 步，占位变 2 bit（起格变空、落格变满）。
- 允许少量不匹配（如 ≥30/32 正确且无误报）应对遮挡/分割误差。
- 若晚到「开局 + 1 步」，可检测出那 2 bit 差异，仍能从开局地图还原首步（被走子的身份已知）。

### 9.6 from→to 检测：占位向量「稳态→稳态」分段

每帧 SAM + 90 交点得到 90bit 占位向量，但**不要逐帧 diff**——走子的中间态（棋子被拿起 / 手遮挡）会破坏「只变一个子」的假设。

**做法**：把占位向量看成**分段常数**的时间序列，走子 = 两个稳态段之间的跳变。

```
1. 检测「稳态段」：连续若干帧占位向量完全相同的区间
2. 一次走子 = 相邻两个稳态段的跳变：源格(1→0) + 目标格(0→1)
3. 「只变一个子」先验用在稳态段之间（此时恰好成立），不在任意相邻帧之间
```

**加固**：
- 手遮挡伪变化 → 对占位做时间多数投票（小窗口内该格多数「有子」才认）。
- 代价：encoder 一帧一次，逐棋子 90 次 decoder（或自动掩码生成），离线可接受。

### 9.7 每步走法校验（防污染 + 定身份）

规则传播不是「只 forward 不回头」，**每一步走法都要做运动规则校验**：

| 棋子身份 | 校验动作 |
| :-- | :-- |
| 未知棋子 | 校验 = **帮它定身份**（运动 → 7 类推断） |
| 已知棋子 | 校验 = **验它身份对不对**（合法性哨兵） |

规则既**正向生成**（传播）又**反向验证**（校验），形成闭环，防止「传播一错到底却无信号」。

**注意**：校验失败只告诉你「哪里错了」，不告诉你「错误从哪步开始」——所以校验失败的正确反应是**触发重同步（9.8）**，而非局部修补。

### 9.8 传播断链重同步：约束消解

断链后仍信任三样东西：占位（SAM，可靠）、每颗棋的运动签名（from→to 检测）、颜色（外观）。重同步 = 用它们重建完整 14 类局面。

**步骤**：
1. **按位置跟踪**：从断链点起，按最近交点匹配跟踪每颗占位棋子，累积 K 步（5–10 步）内它的「运动签名序列」（从哪到哪、是否吃子、是否隔子吃）。
2. **逐子消解类型**：每个签名排除一批类型——隔子吃→炮、日字→马、田字→相、直线多步→车或炮、宫内斜一步→仕、宫内直一步→帅、只前进/过河横走→兵。几步后多数棋子类型被唯一锁定。
3. **数量约束兜底**：每方 将1/仕2/相2/马2/车2/炮2/兵5，用「已确定几颗炮」消解「车 or 炮」歧义。
4. **颜色分侧**：外观把 7 类映射到 14 类。
5. **残余歧义不硬猜**：如从没吃子的炮 vs 车运动上分不开 → 标记低置信，等更多步或交引擎合法性裁剪。

**输出**：完整 14 类局面 + 每格置信度。**重同步不需一步到位**，可跑几步逐渐收敛——每颗棋多走一步就多排除一类。

## 10. 采集与标注节奏（视频 → 标签的管线）

> 2026-10-05 补充定案。采集率跟随视频**实际帧率**（不固定）；标注率走**关键帧 SAM + 规则传播**（不逐帧）。数据生成侧 = SAM + 规则（干净 teacher），端侧 = YOLO（学生）；YOLO-in-the-loop 仅作后续扩量选项。

### 10.1 采集率：跟随实际帧率（不固定）

- 视频来自视频网站，帧率无法保证（24/25/30/60fps，甚至 VFR 可变帧率），**不要假设固定帧率**（如 5fps）。
- 管线按「帧序号 / 时间戳」处理，不按「固定间隔抽帧」。
- 等效帧率 ≥ ~2–5fps 即可捕捉每步走子（before/after 稳态 + 若干过渡帧）；更低才需提醒或插帧。
- 建议固定机位（三脚架）录制，简化单应跟踪与段内标签传播。

### 10.2 标注率：关键帧标注 + 规则传播（不逐帧）

逐帧全标是浪费——相邻帧几乎重复，只给 YOLO 冗余样本、增加对重复场景的过拟合。做法：

1. 走子边界检测 → 视频切成「稳态段」（§9.6）。
2. 每段标 **1 个关键帧**（SAM 出 bbox）+ 每步若干**过渡帧**（子被拿起/在途——这是 YOLO 相对整盘分类的鲁棒性卖点，别丢）。
3. 用单应跟踪把关键帧标签**传播**到段内其它帧（相机微抖用 H 对齐即可）。

**两个「逐帧」成本要分开**（细化 §9.6 的昂贵写法）：

| 信号 | 逐帧需要？ | 用什么 |
| :-- | :-- | :-- |
| 占位向量（有子/无子，90bit） | 是（from→to 分段要用） | 便宜二分类（前景 blob / 颜色 / 圆边，§9.5），**不必用 SAM 的 90 次 decoder** |
| bbox（精确单子框） | 否，只关键帧 + 过渡帧 | SAM（GPU） |

量级：一局 ~40 步，关键帧 ≈ 40–120 张，SAM（GPU）标完 ≈ 十几秒；而逐帧标（5fps×30min ≈ 9000 张）要 15–30 分钟且全是冗余。

### 10.3 计算资源与 SAM / YOLO 分工

- **WSL 有 GPU（已确认）**：SAM ViT-B 编码 ~33ms/帧、点提示 ~ms 级，单帧全流程 ~0.1–0.2s——**关键帧用 SAM 直标完全可行**，无需为效率引入 YOLO。
- **架构边界（已定，见 `项目全景梳理与实施方案.md` §6.1）**：数据生成侧（M0–M5）= SAM bbox + 规则身份 + 外观分色（干净 teacher，错误可被结构校验）；端侧（M6–M7）= YOLO-nano（学生）。数据生成侧必须自己把偏移子也标出 bbox，否则 YOLO 继承缺口。
- **YOLO-in-the-loop（可选扩量，暂不启用）**：当需要标几万帧时才上——YOLO 给 bbox+类别+置信度，只留「高置信 + 规则一致」框，可疑框回退 SAM；SAM+规则 保留为**锚点**（每轮抽小批重标检测漂移）。**唯一无规则交叉校验的是颜色**（规则运动色盲），需单独加外观分色兜底。

## 11. 实施结果（2026-10-05/06，M0–M5 已落地）

> 本节的落地细节与踩坑记录见 `项目全景梳理与实施方案.md` §6 及各 `tools/label_real/m*.py` 脚本 docstring。

### 11.1 落地链路（数据生成侧）

```
debug_video_01.mp4（3384 帧，1080×1920 竖拍）
  ├─ M1 交点几何：单应 H + HoughLines 投影 → 90 交点（grid_rms≈0.77px）
  ├─ M2 开局识别：占位网格匹配标准开局 FEN（多子→非标准拒绝，缺子≤2 补齐身份）
  ├─ M3 from→to：占位向量稳态分段 → 每步走法（手遮挡段用「32 子上限+容差」作废）
  ├─ M4 身份传播：规则 forward 传播 + 运动校验（身份自洽）
  ├─ M5 bbox：SAM 逐子检测（90 中心点 + 8 邻域探针 + IoU 去重）→ 补漏（身份有但 SAM 漏）
  └─ 导出 m5_samples_v3.json（5636 框 / 184 关键帧）→ YOLO 数据集
```

### 11.2 关键结果

| 阶段 | 结果 |
| :-- | :-- |
| M0 SAM 逐子分割 | board_21 检出 35 棋子 mask（圆度 0.84–0.91），空交点零误报 |
| M5 bbox 组件 | board_21 **38/38、0 误报**（M0 基线 35 + 邻域探针补漏 + 一对一分配 + IoU 防重） |
| M3 视频 from→to | 占位分类正解 = **grayMin**（反光免疫），非 std；手遮挡是第二污染源 |
| YOLO 训练（v3） | val mAP50=0.9706、mAP50-95=0.9074（1114 实例） |

### 11.3 踩坑与修正（影响数据质量的 3 件事）

1. **SAM 漏检低对比黑子**（底线将/士/象/马/炮）：单点提示在密集处「桥接」两颗子 → 必须 `largest_component_mask` 抠单颗；漏检子用「身份已知但 SAM 没检出」→ 固定框补漏（0.9 格、交点居中）。否则 YOLO 继承缺口。
2. **随机划分造成 train/val 泄漏**：同段相邻帧 80/20 随机分 → val mAP 虚高 0.988；改用「每段代表帧」诚实划分后才见真实泛化（0.97）。
3. **段边界帧重复采样**：相邻两段边界帧各采一次 → 150 重复样本；按 `(frame,f,r)` 去重保首条。

### 11.4 剩余域差与数据飞轮

- **跨场景仍有域差**：board_21（另一套真实棋盘）测 29/38（黑方全中、红方漏 2 马 + 1 炮）。单视频训练覆盖不了新棋盘/新光照。
- **飞轮闭环（端侧 → 离线 → 重训）**：
  1. 端侧跑通后，真机采集「低置信 / 检测失败 / 局面非法」的困难帧落盘。
  2. 离线用「YOLO-in-the-loop + 规则校验」给新帧自动打标（YOLO 高置信 + 规则一致的框直接留，可疑框回退 SAM+规则当锚点）。
  3. 定期合并新样本重训，OTA 更新端侧 ONNX。
- **冷启动门槛**：v1 模型必须「够用」才能采到有效数据；当前同场景可用、跨场景待补，首版先锁定「采集时棋盘风格」以缩小域差。

## 12. 身份识别备选：OCR 读字 / 单字分类器（2026-10-07 验证，暂不执行）

> 探索「用开源文字识别辅助确认棋子身份」的可行性。结论：通用 OCR 读字不可行；自训单字分类器架构上可行但暂缓，等「准身份标签」就位再启动。

### 12.1 验证结论（开源 OCR 读字）

用 RapidOCR（PP-OCRv6 rec，PaddleOCR 的 ONNX 版，无 paddle 依赖、CPU 可跑）验证：

| 测试对象 | 读对率 |
| :-- | :-- |
| 合成印刷体单字（黑体白底，11 个象棋字） | **11/11 = 100%** |
| board_21（480×640 小图，38 子） | 0/38 |
| debug_video_01 frame500（1080p，标准开局 32 子） | **3/32 ≈ 9%** |

已穷尽优化：原方向 / 180° 旋转、48–128 多档尺寸、灰度 CLAHE / Otsu / 自适应阈值 / 形态学去噪、简体 + 繁体字表。读对率仍 ~9%。

**根因 = 域差**：PP-OCR 训练数据是「印刷体简体文本」，真实棋子是「书法体繁体字（馬/車/將…）+ 薄墨低对比 + 木纹背景 + 斜拍透视」。与角点模型合成失效、Swin 整盘分类 0.83 同类。

**结论**：通用 OCR 读字 ~9%，连「辅助确认」都够不上（辅助需 ≥60–70%），**放弃**。

### 12.2 备选：自训 11 类单字分类器（暂不执行）

若未来要独立于 YOLO 的身份识别器，可训「正视角单字分类器」：

- **输入**：SAM/检测框 → 单应 warp 到正视角 → crop 单字 patch（结构先验净化，无背景、方向/尺度归一）。
- **任务**：11 类（或 14 类）纯分类，比 YOLO 检测+分类简单得多。
- **架构优势**：输入归一化后「只学字、不学位置/角度」，跨场景域差天然比 YOLO 小。
- **天花板 = 标签质量**：与 YOLO 同源——标签来自「规则/标准开局/运动传播」才准；来自 YOLO 提议则自举退化、效果不超 YOLO。
- **执行时机**：等 M3/M4 视频规则传播能稳定产出「准身份标签」后再训；当前不启动。

> 一句话：单字分类器不是 YOLO 的替代，而是「准标签」更好的一个归宿；在准标签就位前，它与 YOLO 卡在同一处。
