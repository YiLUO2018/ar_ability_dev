1. **棋子识别契约错配**：阶段 1 实际训练的是「整盘分类器」（一次出 90 格），而早期脚手架 `TFLitePieceRecognizer` 写的是「逐格分类」（90 次推理，且输出 `[1,15]`）。重写为整盘版，推理次数 90→1，契约对齐训练模型的 `[1,15,10,9]`。

## 2026-10-02：阶段 1.5 — 真实数据自动标注（网格几何精修，进行中）

把「真实照片自动标注」落地为 `tools/label_real/` 的几何精修模块，解决合成→真实域差。方案见 `docs/真实数据自动标注方案.md`。

### 已完成
| 文件 | 说明 |
|:--|:--|
| `tools/label_real/geometry.py` | canonical 几何常量 + 单应/正交/宽高比工具 |
| `tools/label_real/lines.py` | Canny + HoughLines 直线检测 + 水平/垂直分族 + rho 聚类 |
| `tools/label_real/refine.py` | **核心**：`refine_corners` 几何精修（rectify → 网格拟合 → 单应校正） |
| `tools/label_real/validate_synthetic.py` | 合成数据量化验证（扰动粗角点 → 精修 → 对比 GT） |
| `docs/真实数据自动标注方案.md` | 方法 A（SAM 粗定位）/ B（几何精修）/ C（时序投票） |

### 方法（refine_corners）
1. 粗 4 角 → 初始单应 H（canonical → image）。
2. rectify 到正对棋盘（解决棋盘任意倾斜问题）。
3. 直线检测（高 Hough 阈值滤掉棋子/文字伪线）→ 匹配 canonical rank/file → 交叉出节点。
4. `cv2.findHomography(RANSAC)` 拟合残差单应 D，`H ← H@D` 迭代。
5. 质量闸门：grid_rms 没变好则回退粗角点。

### 验证结果（合成 640×640，扰动粗角点）
- 粗角点噪声 10px（≈模型实际输出）→ 角点误差 **降约 26%**（11.7px → 8.7px）。
- 理想（0px）→ 下限约 1.6px（镜头失真 + 检测噪声）。
- 噪声 20px+ → 收益有限（略变差，闸门回退）。

### 遇到的问题与解决
1. **`cv2.getPerspectiveTransform` 要求 float32**：geometry.py 里误传 float64 → 断言失败，改为 float32。
2. **棋盘倾斜时 `split_hv`（固定 0°/90°）失效**：最初在图像空间直接分横竖线，倾斜棋盘（~41°）几乎检不到线 → 改为**先 rectify 到正对**再做直线检测。
3. **Hough 阈值过低导致聚类失败**：阈值 80 时棋子边缘/文字伪线污染聚类，网格线位置错乱；阈值 ~140 时才能干净检出 10 横 + 9 竖。
4. **粗角点带噪声时残差是投影变换**：等距网格拟合（offset+k*spacing）在残差含透视时发散 → 改为「节点 → 完整单应」RANSAC 拟合。
5. **密集棋子 + 楚河汉界 + 镜头畸变**：网格线被遮挡/打断/弯曲，Hough 检测精度 ~2~5px，未达亚像素。

### 遗留 / 下一步
1. 亚像素直线检测（LSD / 投影剖面亚像素拟合）+ 镜头畸变标定，突破 ~1.6px 下限。
2. 接入 SAM 粗定位（方法 A）缩小 ROI、去除棋子干扰。
3. 方法 C（棋子时序投票 + 合法性）待阶段 2 整盘分类输出。
4. 真机采集 → 全自动标注 → 混合微调。

按方案 v2 搭建 `tools/train/`，用阶段 0 的合成数据训练两个模型并导出 TFLite，端到端数值验证通过。

### 已完成
| 文件 | 说明 |
|:--|:--|
| `tools/train/models.py` | `CornerModel`（热力图 + DSNT 软 argmax）+ `PieceClassifier`（整盘 10×9×15）+ 导出包装 |

| `tools/train/export.py` | `litert_torch.convert` + `edge.export` 导出 TFLite |
| `tools/train/README.md` / `requirements.txt` | 用法与契约 |

### 模型契约（导出后 TFLite）
- **board_corner.tflite**：输入 `[1,320,320,3]` RGB `[0,1]` → 输出 `[1,12]`（四角 TL,TR,BR,BL 归一化坐标 + 各自置信度，用于「无棋盘」门控）。
- **piece_classifier.tflite**：输入 `[1,400,360,3]` RGB `[0,1]` → 输出 `[1,15,10,9]`（rank-major 15 类 logits）。

### 训练结果
- 角点：验证集热力图 MSE 0.002；角点坐标**中位误差约 8px**（@320），长尾有离群（p90 约 78px），由置信度门控 + 端上时序平滑兜底。
- 分类：验证集 **99.99%** 准确率（合成数据），第 24 epoch 有一次 loss 尖峰后自行恢复，best 取自尖峰前。

### 遇到的问题与解决
1. **DSNT 网格 buffer 非连续**：`torch.meshgrid` 生成非连续视图，`load_state_dict` 报「multiple elements refer to one location」→ 改用 `expand().contiguous()` 显式内存布局。
2. **导出布局为 NCHW**：`litert_torch` 默认保留 NCHW，与 Android 端 NHWC 契约不符 → 导出包装内 `permute(0,3,1,2)`，使 TFLite 输入为 NHWC；已用 `ai_edge_litert` 验证输入/输出签名与数值一致性（max diff < 1e-5）。
3. **WSL 读 /mnt/l 慢**：训练数据在 Windows 挂载盘上每 epoch 读约 2.4GB，极慢 → 复制到 WSL 原生盘 `/home/leu/chess_data/` 后训练加速到分钟级。
4. **GPU 中途掉线**：训练中 CUDA 失效（`cudaGetDeviceCount` 报错）导致分类训练落到 CPU → 重启 WSL 后 GPU 恢复，重训完成。

1. 阶段 2：Android 集成 — `KeypointBoardDetector`（角点模型 + 单应）+ 整盘 `TFLitePieceRecognizer` + UI 叠加。
2. 真机实拍验证角点/分类准确率与端到端延迟。

## 2026-10-02：真机调试 — 修复棋盘定位

真机验证时发现棋盘检测失败（画面无黄色外框）。通过把检测器输入帧与边缘图落盘分析，定位到两个根因并修复。

### 根因
1. `GridBoardDetector.houghLines` 的非极大值抑制（NMS）存在坐标不统一 bug：比较「原始 rho 索引」与「rho 值（已减 diag）」两个不同量纲，导致 `tooClose` 恒为 false、NMS 完全失效，单帧产出 3.5 万个伪峰值，min/max 取角被噪声污染。
2. 分类阈值 `SIN_THRESHOLD=0.7071`（45°）过宽，棋子圆边等斜向边缘被误判为横/竖直线，污染直线集合。

### 修复
- 修复 NMS：统一在「原始 rho 索引」坐标系内比较，抑制后再转换为 rho。
- 收窄方向带：横线 84°–96°、竖线 0°–6°/174°–180°，过滤斜向噪声。
- 增加票数过滤（保留 ≥ 最高票 45% 的直线）与贴图像边界的伪直线剔除。
- 修正直线位置计算（取图像中心列/行处的 y/x），替代 `rho/sin`、`rho/cos` 的近似。

### 验证
- 真机出现黄色棋盘外框（透视梯形，正确框住棋盘，外框下方为木色桌面、内部为棋盘）。
- 「下一步」可触发走子建议（系统 Toast 出现）。

### 遗留
1. 棋子识别（模板匹配）为占位实现，准确率低，需替换为 TFLite 15 类分类模型。
2. 棋盘定位仍需在更多光照/角度下微调；后续接 OpenCV（设计文档阶段二）提升鲁棒性。
