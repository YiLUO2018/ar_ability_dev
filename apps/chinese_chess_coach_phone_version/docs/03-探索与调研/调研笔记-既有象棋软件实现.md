## 1. 两大技术范式

| 范式 | 输入 | 定位方式 | 代表 |
| :-- | :-- | :-- | :-- |
| **屏幕识别** | 手机/电脑屏幕截图 | YOLO 直接检测「棋盘框 + 棋子」，用棋盘框 bbox 反推网格 | chess-dike、VinXiangQi、atopx/chessboard |
| **物理棋盘** | 摄像头对准真实棋盘 | 显式检测棋盘四角（OpenCV / ArUco / 神经网络）→ 单应变换 → 网格 | chinese-chess-helper、atopx/xq-vision、CMU/IWannaPlay 研究 |

> 本项目属于**物理棋盘**范式，与 chess-dike 的屏幕识别范式不同——这是 chess-dike 模型泛化风险的根本来源。

## 2. 代表性项目

### 2.1 chess-dike（屏幕识别，YOLO）——用户选定的模型来源
- 模型：`yolov5n_xq_fp16.tflite`，权重来自 VinXiangQi，ONNX→TFLite(fp16)。
- 输入：屏幕帧 **letterbox 到 640×640 RGB**。
- 输出：**15 类 = 14 种棋子（红黑各 7）+ 1 个棋盘框**。
- 后处理：解码 → 类别感知 NMS → 置信度/宽高比/尺寸一致性过滤（排除工具栏按钮、"轮到谁"标记盘）。
- 网格映射：**棋盘框宽/8、高/9 求格距，棋子中心 round 到最近交叉点**。
- 朝向判断：由帅/将位置判断屏幕朝向后镜像到「红恒在下」坐标系；再做数量/将帅/上限合法性校验。
- 引擎：Pikafish。显示：悬浮窗迷你棋盘 + 箭头标注最佳走法。
- 许可：GPL-3.0。

### 2.2 VinXiangQi（屏幕识别，YOLOv5，权重来源）
- C# + ONNX Runtime；模型 `nano.onnx` / `small.onnx`，输入 640×640。
- 15 类（7+7 棋子 + 棋盘）；三层锚框（stride 8/16/32）；置信度阈值约 0.7。
- 数据集：宣称 >10 万张不同光照/角度图像。

### 2.3 atopx/xq-vision（物理/图片，两阶段 ONNX）——最接近我们**原**架构
- 两阶段：`BoardDetector`（预测四角）→ `warp_board`（校正到 canonical 450×500）→ `PieceRecognizer`（分类 10×9 格子）。
- 与我们「透视校正 + 逐格分类」同思路；ONNX、不随附权重。

### 2.4 chinese-chess-helper（物理，OpenCV 传统）
- 定位：Canny 边缘 + 最大四边形轮廓 → 透视变换。
- 网格：Hough 直线 → 求 9×10 交叉点。
- 棋子：HSV 颜色分割区分红黑 + 模板匹配 / Hu 矩匹配识别字形。

### 2.5 物理棋盘研究（CMU Guided Chinese Chess / IWannaPlay / ChessAI）
- 对齐：**ArUco 标记 + 单应变换**（比纯棋盘角点更稳）。
- 识别：YOLOv8 / YOLOX 检测棋子。
- 提示：CMU 在 9×10 交叉点下嵌 **SK6812 可寻址 LED**，用颜色高亮合法走法/推荐着法（物理高亮）；IWannaPlay 用屏幕动态可视化。

## 3. 棋盘定位方法汇总

| 方法 | 说明 | 适用 |
| :-- | :-- | :-- |
| OpenCV Canny + Hough 直线 + 极值求角 | 传统、自包含 | 物理棋盘（本项目当前实现） |
| 最大四边形轮廓 + 透视变换 | 简单、对光照敏感 | 物理棋盘 |
| ArUco 标记 + 单应变换 | 稳、需贴标记 | 物理棋盘/机器人 |
| 神经网络检测四角（xq-vision BoardDetector） | 鲁棒、需训练模型 | 物理棋盘 |
| YOLO 检测「棋盘框」类 | 免校准 | 屏幕识别 |

## 4. 棋子识别方法汇总

| 方法 | 说明 | 适用 |
| :-- | :-- | :-- |
| 模板匹配 / Hu 矩 | 传统、快、对字形字体敏感 | 规整图像 |
| HSV 颜色分割（红黑）+ 模板 | 传统、区分红黑 | 物理棋盘 |
| 逐交叉点分类 CNN（15 类） | 需透视校正 + 模型 | 物理棋盘（本项目原方案） |
| YOLO 检测（14 类 + 棋盘框） | 免逐点、端到端 | 屏幕/物理（需对应数据） |

## 5. UI 叠加 / 走法提示方法汇总

| 方法 | 说明 |
| :-- | :-- |
| 屏幕悬浮窗迷你棋盘 + 箭头 | chess-dike：走法画在迷你棋盘上（非原棋盘叠加） |
| 原画面叠加箭头/高亮 | 用棋盘单应矩阵把 grid 坐标映射回画面（本项目目标） |
| 物理 LED 高亮交叉点 | CMU：棋盘下嵌 LED，颜色提示走法 |

## 6. 对我们方案的启示

1. **网格↔画面映射是所有方案共同的刚需**，印证「保留棋盘定位」正确：屏幕方案用棋盘框 bbox 反推，物理方案用四角 + 单应。
2. **chess-dike 的 15 类（14 棋子 + 1 棋盘框）输出可直接复用**：输入 640×640 letterbox、YOLOv5 解码 + 类别感知 NMS、棋盘框宽/8 高/9 → 交叉点。但它是**屏幕数据训练**，对实拍需真机验证。
3. **可选路线**：若实拍泛化差，可借鉴 xq-vision 的「四角检测 + 透视校正 + 逐格分类」两阶段（回归我们原架构，但换 ONNX/自训模型），或参考 chinese-chess-helper 的 OpenCV 传统路线。
4. **走法合法性校验**（数量/将帅/上限）是识别结果的重要兜底，chess-dike 已这么做，我们也应在 `buildBoard` 后加一层校验。
