# IMU 静止分支设计方案

> 日期：2026-10-12 ｜ 状态：**已确认，实施中**（S7 配置移植 + 本方案同批落地；PC 模拟验证见 §7.1 结果，真机矩阵待跑）
> 背景：vis2b 回放遗留 7 个问题帧，根因定案为三类（开发日志 2026-10-12）：A 手遮挡漂移骗过包含门、B 丢失清屏闪烁、C 投票幽灵。本文是治这三类的确定性方案。
> 关系：本文是《算法梳理-01棋盘检测.md》§9（C9 BoardTracker，T1 视觉→T2 IMU→T3 完整）的**前置简化项**——不动几何传播、不做时间戳对齐，只用 IMU 回答一个问题：「手机现在动没动」。

---

## 1. 目标与非目标

**目标**：IMU 提供独立的（非视觉的）「手机静止」证据，用于三个决策：
- D1：静止 + 检测结果漂移 → **拒绝漂移**（治类型 A，f189/f321/f474）；
- D2：静止 + 连续漏检 → **不清屏**，保持显示（治类型 B，f595/596）；
- D3：静止期间投票只收「未被拒的好帧」+ 合法性门（治类型 C，f868）。

**非目标**（明确不做，走 §9 排期）：
- 移动时的 IMU 几何预测（rotation 单应外推，T2/T3）；
- 逐帧 IMU-相机时间戳对齐（静止分支用滑窗统计，天然不需要）；
- 检测频率优化 / overlay 帧率提升（C9）。

## 2. 核心思想

现状所有闸门（跳变闸/EMA/包含门）都从**视觉行为**反推「手机没动」——慢（fail_streak 要攒 5 次 ≈ 5 个检测周期）且可被欺骗（手遮挡期的漂移逐帧小于跳变阈值）。IMU（陀螺仪+加速度计，100Hz+，零推理成本）在 ~1s 内给出独立判定：

```
IMU==STATIC（手机没动）⇒ 画面里棋盘四角不可能真移 ⇒ 一切大幅漂移必为伪 ⇒ 冻结。
IMU==MOVING ⇒ 现有移动路径照常（中心救援 + fail_streak≥5 失效 + 无锚约束）。
```

教练场景主使用方式是固定机位（支架/桌面支架），静止分支覆盖绝大多数使用时长。

## 3. 传感器与静止判据

### 3.1 传感器

| 传感器 | 用途 | 采样 |
|---|---|---|
| `TYPE_GYROSCOPE`（rad/s） | 旋转检测（最灵敏的移动证据） | SENSOR_DELAY_GAME（~50Hz） |
| `TYPE_ACCELEROMETER`（m/s²） | 平移/振动检测（‖a‖ 对重力的偏离） | 同上 |

不需要融合传感器（rotation vector 是 T2 的事）。两个传感器回调里只做 O(1) 累加（环形缓冲，预分配），不分配对象；统计量由 processFrame 通过 volatile 快照读取。

### 3.2 判据（滑窗 T_WIN = 0.5s，最近 ~25 个样本/传感器）

```
gyro静:  窗内所有样本 |ωx|,|ωy|,|ωz| < GYRO_STATIC_MAX        （覆盖 bias：真静止残差典型 <0.02 rad/s）
acc静:   窗内 ‖a‖ 的标准差 < ACC_STD_MAX
         且 窗内 ‖a‖ 均值 ∈ [ACC_NORM_LO, ACC_NORM_HI]        （≈9.8±0.5）
```

三态输出：`STATIC / MOVING / UNKNOWN`（传感器缺失、注册失败、上电窗口不足 → UNKNOWN）。

### 3.3 状态机迟滞：**进慢出快**

- 进 STATIC：判据需**连续满足 T_HOLD_IN = 1.0s**（防止移动中的瞬时安静期误入静止）；
- 出 STATIC：任一窗口判据破坏**立即**转 MOVING（宁可保守——静止特权只该在真静止时给）。

### 3.4 已知盲区（诚实记录）

- **匀速纯平移**：无旋转、加速度计只读重力 → 误判静止。现实中持续 0.5s+ 无旋转的匀速平移极罕见，且 D1 的棋盘移动仲裁（§5.4）兜底：视觉持续不一致 → 重锚，不会锁死错误状态。
- **OIS**：镜头防抖补偿手持微抖 → IMU 判 MOVING 而画面稳——保守方向误判（走现有移动路径），无害。反方向（IMU 稳画面动）是主动机构才会出现，OIS 为被动补偿，不存在。

## 4. 静止锚（Frozen Anchor）

锚 = 静止期间被认可的棋盘四角，是 D1 的比对基准。

**建立**（需同时满足）：
- IMU 已进入 STATIC；
- 连续 `ANCHOR_SETTLE = 5` 次检测成功，且任意两次四角平均位移 < `ANCHOR_JITTER = 5px`（贪心计数：新检测与当前候选锚偏差 <5px → 计数+1，否则清零重来）；
- 达标后锚 = 这 5 次检测的四角中位数（滚动窗初始化为这组）。

**滚动维护（2026-10-14 定稿，vis5/6 教训）**：有锚后被锚闸**接受**的检测进滚动窗（cap `ROLL=8`），锚 = 窗中位数——SAM 检测自身有 ±20-40px 分钟级慢漂（box 提示随棋子走子呼吸），固定锚会与稳态检测互斥卡死；中位数跟随慢漂且抗 ≤3 帧突变。

**显示=锚（用户标准「静止场景四角应完全一致」的直接实现）**：静止+有锚时 detect 输出锚四角（跳过 EMA、refineQuad 旁路）——显示构造上恒定，只在锚滚动更新时 ≤数 px 微移；检测降级为「锚的维护者」，其慢漂不再进显示。

**失效/重建**（任一）：
- IMU 离开 STATIC → 清锚（下次静止重新积累）；
- 挪盘双确认通过（§5.4）→ 清锚走无历史重锁；
- 现有 unlock 清屏路径走到 → 清锚。

## 5. 决策点与代码挂钩

### 5.1 D1 锚闸（治 A）——放检测器内部，EMA 更新之前

位置：`SegmentationBoardDetector.detect()` 内，在 selectCandidate 成功后、跳变闸/EMA 之前（与 isQuadJump 同级）。这样拒绝时 prevCorners/EMA 不被污染，上层按普通「漏检」走迟滞保持。

```
锚存在 && IMU==STATIC && 新四角任一角与锚位移 > ANCHOR_CORNER_MAX(0.2 格)
  → 返回 null，anchorRejects++（并记录被拒四角）
```

- 格宽按锚自适应：锚四角对角线 D → 格宽 ≈ D × (50/672.7)，阈值 0.4 格 ≈ 0.03×D。video_01 问题帧漂移 25-110px、正常帧角点抖动中位 4px，0.4 格（~40px@该视频）区分度充足。
- 0.4 格内的**小偏移照常接受**（EMA 微调），锚不是硬冻结——掩码好帧仍可轻微修正锚（见 §5.4 慢更新）。

### 5.2 D2 静止不清屏（治 B）——unlock 条件加 IMU 条件

`MainActivity.processFrame` 的 unlock 分支（lockMisses > LOCK_MAX_MISSES 处）：

```
if (imuState == STATIC && latestBoardInfo != null) → 不清屏，显示保持，检测层照常 fast-sampling 重试
else → 现有清屏逻辑（含 resetTrackingState）
```

静止期显示持续不闪（f576-f610 手走子全程框稳定）；重锁成功后无缝换新框。可选：overlay 加「静止保持」小角标区分状态。

### 5.3 D3 投票保护（治 C；v2，vis3 实测教训）

- 主力：D1 已把漂移帧拒在 push 之外——投票窗里只剩好帧，幽灵自然消失；
- 保险门 v2（无论 IMU 都生效）：`voted 子数 > 32`（幽灵膨胀）**或** `voted 子数 < 合法参照 × 0.6`（遮挡期检出塌方，如 f596 的 8 子）→ 撤销本帧 push、显示沿用合法参照；**接受的合法投票才更新参照**（lastLegalGrid 单独维护）。
- ⚠️ v1 教训（vis3 实测）：用 `isIllegalPosition` 当**拒绝**条件会因 YOLO 偶缺一帅而逐帧全拒 → 窗口 pop 冻结 → 局面永久卡在首个投票（实测恒 25 子）。isIllegalPosition 只用于**参照维护**（什么算合法），不用于拒绝——缺一子的局面只是不完整，不是错。

### 5.4 挪盘兜底（IMU 盲区；2026-10-13 定稿 = **双确认超时**）

IMU 只证明手机没动，**不能证明棋盘没动**——偶发人为挪盘需要兜底，但单条件仲裁已四轮证伪：

- v1 六连击一致性：手部漂移与真挪盘在「连续一致」上不可分（vis3 f330/f1291/f1370 全是误仲裁）；
- v2/v3 超时 30/60 裸重锚：全管线长遮挡段攒满阈值在漂移位重锚（vis4 实测 6 次误仲裁 → 幽灵帧；遮挡期 YOLO 质心 <10 个，包含门失效，漂移候选直达锚闸被拒攒计数）；
- **v4 定案 = 三层双确认**：

```
① 超时询问：连续 60 次拒绝且无一接受（任一锚内接受即归零）
② 几何确认：被拒四角相对锚为四角整体平移（每角位移 >0.5 格）
   ——真挪盘四角全动；手遮挡漂移只变形 1-2 角
③ 内容确认：上层用候选四角跑 YOLO 取当前帧棋子质心，
   包含率 ≥95% 且 ≥10 个——棋盘被挪则棋子随行；遮挡期质心不足天然不通过
→ 三层全过才清锚重锁（清历史+清参考）；任一不通过 → 重置计数继续攒，保持显示
```

- 快路径仍是**碰手机**（IMU→MOVING 秒级清锚）；双确认兜底覆盖「静止手机 + 真挪盘 + 不碰手机」的长尾，代价 ~1-2 分钟恢复。

### 5.6 救援分级（实施中修订，PC trace 教训）

原设计未涉及救援路径的参考取舍，实施时首版用「IMU 静止→带参考，否则绕过」的双分支，**PC trace 实测证伪**：UNKNOWN/模拟关闭下手遮挡视频的残缺候选借救援混入（err>15px 53%，比 S7 的 20.4% 大幅回归）。修订为**分级救援 + 三态门**：

```
救援（中心提示重跑 decoder 后）：
  ① selectCandidate(带参考)                     ← STATIC/UNKNOWN 只走本级（=S7 行为）
  ② 全拒且 ImuMotion==MOVING → selectCandidate(无参考)  ← 板已移走、参考陈旧，移动重锁专属
```

- 静止场景：①即成功（参考仍有效，包含门挡残缺候选）；
- 移动场景：②在 ~1-3s 内重锁（保持真机「不丢了」标准）；
- 传感器缺失（UNKNOWN）：退回 S7 单级行为——移动重锁退化为 unlock 计时路径（~15 漏检后参考清空、无历史重锁），慢但不锁死。
- 接口相应从 `onImuStateChanged(isStatic: Boolean)` 升级为 `onImuStateChanged(ImuMotion)` 三态。

## 6. 参数表（初值与依据）

| 参数 | 初值 | 依据 |
|---|---|---|
| GYRO_STATIC_MAX | 0.08 rad/s | 盖过 residual bias（实测典型 <0.02）；手持微抖 0.1-0.5 会被正确判移动 |
| ACC_STD_MAX | 0.15 m/s² | 静置 ‖a‖ 噪声 ~0.05；触碰/抬起显著更大 |
| ACC_NORM_LO/HI | 9.3 / 10.3 m/s² | 重力 ±0.5 |
| T_WIN | 0.5 s | 响应速度与统计稳定的折中 |
| T_HOLD_IN | 1.0 s | 防移动中瞬时安静期误入 |
| ANCHOR_SETTLE | 5 次成功 | 检测 ~1Hz → 5s 建锚，可接受 |
| ANCHOR_JITTER | 5 px | S7 正常帧角点抖动中位 4px |
| ANCHOR_CORNER_MAX | **0.2 格**（10-13 收紧自 0.4） | 好帧抖动 p95≤11px ＜0.2格；实测单角 max 125→21px、TR>15px 30.2%→0.2% |
| ANCHOR_REJ_TIMEOUT | **60 次**（10-13 定案） | 超时仲裁重锚。A/B：30 仍被长遮挡段误触发（TR 12.2%）；60 全视频 0 触发；真挪盘恢复 = 60 次拒绝或碰手机（IMU 即清锚） |
| LOCK_MAX_MISSES | 15（S7 值） | 静止分支落地后实际很少走到清屏 |

传感器阈值以真机静置实测微调（首轮实现时加 30s 采样落盘：窗内 gyro max / acc std，用实际分布定阈值）。

## 7. 验证方案

### 7.1 PC 模拟（先于真机，replay_pipeline.py 加 `--imu static|moving` 开关）

- `--imu static`：恒 STATIC + 锚闸 + 不清屏 → 跑 video_01 全程，预期 7 问题帧全部消失：err>15px 20.4%→ 个位数%、清屏 0 次、>32 帧 0、f189/f321/f474 漂移帧被拒；
- `--imu moving`：行为与现 S7 完全一致（门全放行）——确认静止分支不伤移动路径；
- 模拟「静止中棋盘被挪」：中段人工把锚偏移 1 格注入，验证双确认超时（整体平移 + 新位置质心包含）在 ~60 次拒绝后重锚；单角漂移注入应永远不重锚。

### 7.2 真机场景矩阵（证据走落盘，设备 logcat 被过滤）

| # | 场景 | 预期 |
|---|---|---|
| 1 | 支架静止 + 对局走子 5 分钟 | 0 漂移采纳、0 清屏、局面稳定、锚事件日志正常 |
| 2 | 手持持续移动 1 分钟 | 移动路径正常重锁，锚不误伤（IMU 判 MOVING） |
| 3 | 静止中把棋盘挪 10cm（手机不动） | 快路径：碰手机秒级重锚；兜底：双确认超时 ~1-2 分钟内重锚（几何整体平移 + 新位置质心包含双确认） |
| 4 | 纯静止 10 分钟 | 无 flicker，锚拒绝误报率 ~0 |

落盘：状态转换/锚建立/锚拒绝/仲裁事件写 `filesDir/debug/imu_events.log`（JSON 行）。

### 7.3 单测（JVM）

合成传感器序列验证静止判据与迟滞；锚状态机（建立/失效/仲裁）；投票合法性门。

## 9. 风险与回退

- 全部门以 `imuState==STATIC` 为前提，UNKNOWN/MOVING 时行为 = 现状 → **传感器异常自动退化为当前版本**，无新增崩溃面；
- 阈值过松（误判静止）→ 漂移靠仲裁兜底、棋盘挪动靠重锚；阈值过紧（误判移动）→ 退化为现状，无损失。两方向失败模式都安全；
- 唯一硬风险：锚闸拒绝过猛导致静止场景长时间无检测更新——由「0.4 格内照常接受 + 锚慢更新 + 仲裁」三重缓解。
