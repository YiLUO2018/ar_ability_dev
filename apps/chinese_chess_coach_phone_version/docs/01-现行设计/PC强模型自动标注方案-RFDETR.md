# PC 强模型自动标注方案（RF-DETR）——方案 A

> 日期：2026-10-15 ｜ 状态：**定稿待实施**（用户已确认方向与更大模型诉求）
> 取代：《棋盘检测模型spike方案.md》（B 计划升级版，该文档转为历史）
> 决策链：真机验证实证 SAM+规则级联上限低（语义在规则不在模型；f426-f476 的 debug 史即规则补丁史）+ EdgeSAM 1s 帧率容错小 → 根因=**标注产能** → PC 强模型自动标注解锁数据 → 端侧蒸馏轻量统一模型收尾。
> 硬件：PC = RTX 4060 8G（WSL GPU 训练路径已验证，train_yolo.py 同链路）。

## 1. 目标与非目标

**目标**：
- G1 棋盘自动标注：box + 4 角点（TL,TR,BR,BL，对齐 `BoardGeometry.physicalCorners` 约定），几何精度目标 ≤10px（vs 人工 GT）
- G2 棋子自动标注：box + 14 类身份（**类别序对齐现有 YOLO 契约——车在马前**），解中局身份标注死锁（2026-10-07 教训）
- G3 产出端侧统一模型训练集 **v10**：单一 YOLO-pose（棋盘 4 角点 + 棋子框/类）一次前向出全部
- G4 飞轮闭环成型：新视频 → 自动标注 → 交叉校验+抽检 → 增量训练 → 端侧模型升级，全流程可复跑

**非目标**：端侧跑 RF-DETR（参数量最小 30M，手机 CPU 不现实——RF-DETR 只当 **PC 标注器 + 蒸馏教师**）；VLM 交互（方案 B，见 §10）。

## 2. 模型选型（8G 4060 约束下用更大模型的可行性）

RF-DETR 家族（Roboflow，Apache 2.0，DINOv2 底座 + NAS 扩展，[官方文档](https://rfdetr.roboflow.com/latest/learn/train) / [GitHub](https://github.com/roboflow/rf-detr) / [NAS 论文 arXiv:2511.09554](https://arxiv.org/html/2511.09554v1)）：

| 变体 | 参数 | COCO AP | 定位 |
|---|---|---|---|
| N (Nano) | ~30M | 48.0 | 端侧蒸馏参考（不直接部署） |
| S (Small) | ~32M | — | 8G 微调舒适 |
| M (Medium) | — | ≈MaskDINO 级 | **标注主力（默认）** |
| B (Base) | 29M | 53.3 | 初版变体，8G 微调舒适 |
| **L (Large)** | **128M** | **56.5** | **上限尝试（用户诉求）**：batch 2 + grad_accum 8 + AMP + 512 输入；OOM 则回落 M（DETR 二次注意力显存高，已有 OOM issue 前例，batch_size="auto" 探测） |

**结论：主力 M、上限 L、全部在 PC 离线跑（吞吐不敏感，标注时长换精度是划算的）。** 端侧部署模型不是 RF-DETR——蒸馏/转标到 YOLOv8n-pose 量级（3-4M，480×640 端上 20-50ms）。

## 4. 标注任务定义

- **任务一 棋盘**：class=board 的 box + 4 keypoints。先独立微调一个 RF-DETR（任务简单、A 级数据即可启动）。
- **任务二 棋子**：14 类 box。第二个 RF-DETR（复用 v9 数据 + 新伪标签增量）。
- **输出格式**：对齐现有 YOLO 数据集布局（images/labels/data.yaml）+ 新增 YOLO-pose 关键点标签（board 类 4 kpt）。工具放 `tools/label_real/`（rfdetr_label.py / rfdetr_train.py，与 train_yolo.py/export_onnx.py 同链路）。
- 两任务后期可合并为单模型双头（非必须）。

## 5. 自举流程（防自证是命门——本项目已被咬两次）

```
S0 基线微调：A 级数据 → RF-DETR（棋盘任务先行）
S1 伪 GT 扩展：冻结管线（v03_final）在已验证段的输出 → 带置信度入池
S2 批量推理：C 级全帧（M 或 L）
S3 交叉校验闸（三层）：
   ① 时序一致性：同一静止段内四角方差 > 阈值 → 可疑
   ② 与 SAM 管线一致性：分歧 >0.5 格 → 人工抽检队列
   ③ VLM 抽检（方案 B 首个落点）：框内是否棋盘/棋子语义校验
S4 人工抽检：每轮按置信度分层抽 5% review；该层准确率 ≥98% 才放行进训练集
S5 迭代：新标注 → 重训 → 质量提升 → 下一批（飞轮闭环）
```

## 6. 端侧统一模型（最终交付物）

- 架构：**YOLOv8n-pose（或 YOLO11n-pose）单模型**：board(4kpt) + 14 棋子类，480×640 输入。
- 性能预期：端上 XNNPACK 20-50ms → **15-30fps 检测直出**，SAM 的 1s 与整条规则级联退役。
- 端侧架构随之简化：检测直出 → IMU 静止锚兜静止场景 → LK/跟踪降级为可选显示平滑（代码保留，职责降级）。
- 导出：export_onnx.py 扩展 pose 头解码（ONNX 契约变更需同步 YoloPieceDetector.kt）。

## 7. 评测基准

- 棋盘四角：vs board_21 GT + video_03 用户认可 5 帧 + 新采集人工抽检（px 级，标准沿用 ≤15px/角）。
- 棋子：val 拆分 mAP + 中局身份抽检（此前死锁场景）。
- 端侧：真机耗时（对标 EdgeSAM ~1s）+ 全场景矩阵（静止/移动/斜角/遮挡/挪盘）。

## 8. 里程碑

| 里程碑 | 内容 | 判据 |
|---|---|---|
| **M1'（spike）** | RF-DETR-M 棋盘任务微调（A 级数据）→ video_03 + board_21 评测，对比 SAM 管线（角点误差分布 + 极端斜角段成功率 + L 版尝试） | 中位角点误差 ≤ SAM 管线且极端斜角不劣化 → **Go** |
| M2 | 全量视频自动标注（S2-S4）→ v10 数据集 | 抽检准确率 ≥98% |
| M3 | 端侧 YOLO-pose 统一模型训练 + 真机替换 SAM | 全场景矩阵通过 |
| M4 | 飞轮闭环：周期性重标注重训 | 新场景冷启动 ≤1 轮采集 |

## 9. 风险与回退

- **自证循环**（最大风险）：S3/S4 闸 + 只从验证子集起步；一旦发现某类系统性错误，回滚该批次。
- **L 版 OOM**：回落 M（离线标注吞吐不敏感，损失有限）。
- **DETR 关键点精度**：框回归强但 kpt 头未必——备选：检测 box + 检测框内亚像素角点精修（规则面从「全图级联」缩到「框内精修」，仍是净减法）。
- **域多样性**：现有素材仅 3 块棋盘/有限光照——飞轮采集比以往任何时候都重要（每帧都是训练素材）。

## 10. 与方案 B 的接口（用户已定方向）

**方案 B = 端侧统一 VLM（参考 Qwen3.5-VL-Drive 式结构）**：一个视觉基座，分频双头——检测头高频（渲染/定位）+ LLM 头低频（高质量用户交互）。定位为**长期端侧形态**，近期落点两个：
1. S3-③ 的 VLM 抽检（标注质量闸）；
2. 端侧统一模型（§6）成功后，检测头即 B 的检测头前身——v10 数据集与蒸馏链路直接复用。
约束注记：手机端 VLM 需 1-3B 量化级 + 检测头蒸馏，8G 4060 承担训练/蒸馏。B 的详细方案**已独立建项**：`apps/chinese_chess_coach_pc_version`（PC 端象棋视频识别与走子建议系统，2026-10-16）——方案见其 docs/01-现行设计/VLM架构方案.md；本项目与它的公共资产 = v10 数据集（角点 GT 约定已对齐 BoardGeometry），其检测分支直接以 RF-DETR 为起点。
