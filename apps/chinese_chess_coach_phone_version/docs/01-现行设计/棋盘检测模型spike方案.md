# 棋盘检测模型 Spike 方案（B 计划）

> ⚠️ **本文档已被《PC强模型自动标注方案-RFDETR.md》（2026-10-15）取代**——B 计划升级为 RF-DETR 自动标注 + 端侧蒸馏统一模型。保留作历史。
> 日期：2026-10-13 ｜ 状态：**已确认方向，待实施**
> 背景：SAM+规则在 video_01 逐角评测中 TR 角 30.2% 帧 >15px（max 125px）——SAM 是通用分割器无棋盘先验，遮挡时掩码跟手走属结构性缺陷，规则只能围堵且各有盲区（本周实证：包含门盲区→锚→仲裁误报→投票冻结）。训练专用检测模型做「摊销推理」（从网格线/对边/布局推断被遮角）是结构性出路。
> 前置事实：10-02 合成数据角点模型死于域差（真机垃圾输出+置信度 1.0）——**本方案成立的前提是真实标签**（M3 精修单应 grid_rms 0.77px 已覆盖数千帧）+ YOLO 棋子闭环先例（mAP50 0.885 真机可用）。

## 1. 形态：现有 YOLO 加 board 类 + 4 关键点（不另起模型）

- **一个模型同时出棋盘与棋子**：yolov8n-pose 骨干，新增 class 14 = "board"，带 4 个关键点（TL/TR/BR/BL 物理外角）；棋子类 0-13 不带关键点。
- 理由：完全复用 train_yolo.py / export_onnx.py / YoloPieceDetector.kt 的 letterbox-解码-NMS-部署链；棋盘框与棋子框同帧同坐标系；单次推理 ~150ms（vs EdgeSAM 1604ms，**~10×**）。
- 输出解码：board 框直接给四角（关键点回归），不再走「掩码→凸包→减点」链——角点语义由模型直接学。

## 2. 数据与标签

| 来源 | 帧数（估） | 四角标签 | 说明 |
|---|---|---|---|
| video_01/02/03（M3 精修单应） | ~2600 | 单应反投影 physicalCorners | 主力；含手遮挡段（标签经时间传播，见下） |
| std02（video_label_std 管线） | ~200 | 已验证单应 | 多角度 |
| 飞轮 775 帧 | 775 | metadata 自带 corners + 可离线精修 | 真机跨场景 |
| （后续）网络对局视频 | 不限 | 先用本管线自动标注 | 场景多样性主力，闭环见算法梳理 §10 |

- **遮挡帧标签 = 时间传播**：棋盘静止段内，被遮帧的四角 = 该段干净帧单应（视频内棋子动、棋盘不动）。
- **手部遮挡增强（核心增量）**：同一静止段内，遮挡帧与干净帧做**帧差** → 差分区域 ≈ 手部+移动棋子 → 把手部区域裁出贴到其他干净帧（标签即目标帧四角，天然正确）。扩大遮挡训练分布而不需人工标注。
- 通用增强沿用 v9 结论：**只用 0/90/180/270 四角度**（17 角度几何不一致已被证死）+ 亮度/模糊。

## 3. 训练

- `train_yolo.py` 升级 pose 任务（ultralytics yolov8n-pose.pt 起步）；数据集 yaml 加 kpt 维度（board 4 点，棋子 0 点）。
- 划分守 v2/v9 教训：**按视频段时间序切分**（防相邻帧泄漏）；跨场景验证集（board_21、video_03、飞轮抽样）完全隔离。
- WSL GPU 训练（SAM 禁 GPU 禁令不影响 YOLO）。

## 4. 评测协议（沿用本次「四角恒定」评测，固化为 eval 协议）

1. **video_01 全帧逐角评测**（手机/棋盘静止 → 四角应恒定，GT=全体成功帧中位数）：TL/TR/BR/BL 各报 >8px / >15px / max。基线对照：SAM+S7=TR 30.2%>15px；SAM+锚收尾=TR 0.2%、max 21px（显示层）。
2. **遮挡段专项**：手遮挡时段（本评测 13 段）逐帧角误差——模型必须「看穿」而非靠保持。
3. **留出场景**：board_21、video_03、飞轮帧——跨场景角误差与检出率（防 10-02 式域差崩塌）。
4. **速度**：端侧 CPU 单帧推理耗时。

**晋级判据**：video_01 TR >15px **<2%**（且不依赖静止先验）+ 遮挡段误差与全片持平 + 留出场景无崩塌（角误差 <15px 帧占比 ≥95%）→ 升主检测器；否则回退规则收尾版继续服役，模型仅做候选生成器之一。

## 5. 上线架构（分层，非二选一）

```
YOLO-pose（棋盘+棋子，~150ms/帧）        ← 主检测器：治遮挡语义与 1Hz 延迟
  ├ 锚/IMU/迟滞/投票门（全部保留）        ← 时间层：检测器无关，对模型的错帧同样兜底
  └ EdgeSAM                              ← 降级：模型低置信/几何校验失败时的兜底与冷启动
```
- 模型输出先过轻量几何校验（四角形状闸 + 与上帧棋子质心包含率——现有组件复用），再进锚闸/EMA。
- SAM 保留冷启动价值：换新棋盘/新场景时模型置信低 → SAM 零样本兜底并标注积累 → 下轮数据。

## 6. 工作量与顺序

1. 标签导出脚本（M3 单应 → YOLO-pose 格式，含时间传播）：~0.5 天
2. 手部迁移增强脚本（帧差→贴片）：~0.5 天
3. pose 训练改造 + 首训：~0.5 天
4. eval 协议脚本 + 三场景评测：~0.5 天
5. （晋级后）YoloPieceDetector.kt 解码扩展 + SAM 降级链 + 真机：另计

## 7. 风险登记

| 风险 | 对策 |
|---|---|
| 跨场景域差（10-02 死因） | 留出场景硬门槛；SAM 兜底常驻 |
| 遮挡角标签噪声（传播错） | 时间传播仅取段内 RANSAC 一致帧；增强贴片标签天然精确 |
| 自信地错（置信度高但四角垃圾） | 几何校验（形状闸/包含率/网格线 rms-lite）不信任裸置信 |
| 训练数据仍是少数场景 | 首版只求「不输规则栈 + 遮挡段显著更好」；场景多样性靠网络视频闭环滚动 |
