# 棋盘定位方案探索记录

**日期**：2026-10-02
**状态**：真机验证完成，选定方向 A（轻量分割）为快速落地路线，方向 B（重训角点模型）为后续优化。
**背景**：需要从相机画面中定位真实象棋棋盘的四角，用于透视校正 → 整盘棋子识别 → 走子建议。

**测试样本**：`debug_frames/board_21.png`（480×640，斜拍真实棋盘，棋盘约占画面 21%）。
**真实角点（人工标注，已修正）**：TL(116,77) · TR(346,72) · BR(376,297) · BL(96,306)。

---

## 方法总览与结论

| 方法 | 原理 | 角点误差 | 结论 |
| :-- | :-- | :-- | :-- |
| ① 角点回归模型（合成训练） | 轻量 CNN + DSNT 回归四角 + 置信度 | 垃圾（置信度 ~1.0） | ✗ 域差泛化失败 |

## ① 角点回归模型（合成数据训练）

**原理**：`CornerModel`（`tools/train/models.py`）——轻量 CNN 骨干（3 次下采样到 1/4 分辨率）+ 热力图头 + DSNT 软 argmax，输出四角归一化坐标 + 各角置信度。训练数据为 `tools/data_gen/render.py` 程序化渲染的合成棋盘（4000 正 + 800 负样本）。

**真机结果**：

```
模型输出: [12,170] [41,55] [399,265] [188,50]  conf=0.997
真实角点: [116,77] [346,72] [376,297] [96,306]
```

**优点**：
- 端上推理极快（小 TFLite，单帧毫秒级）。
- 端到端，输出即坐标 + 置信度，天然支持「无棋盘」门控。

**缺点**：
- **合成 → 真实域差**：合成数据渲染的棋盘（规整木纹、干净背景）与真实照片（斜拍、杂乱桌面、真实光照）差异过大，模型学到了错误先验，输出垃圾角点却给出 ~1.0 的置信度，置信度门控完全失效。
- 置信度不可靠，无法用于「无棋盘」判定。

**验证方式**：用 PyTorch 参考实现加载 `best.pt` 跑同一张图，输出与真机日志逐点一致，确认 **Android 端代码（预处理/推理/坐标映射）正确**，问题在模型本身。

## ② OpenCV Hough 从零检测

**原理**：`GridBoardDetector.kt`（Kotlin）与 `tools/label_real/lines.py`（Python）同一思路——灰度 → Sobel/Canny 边缘 → HoughLines → 按「近水平/竖直」固定角度带分族 → 取极值线求外框四角。

**真机结果**：只检出 3 条横线 + 5 条竖线（应有 10 + 9），角点误差 ~155px。

**优点**：
- 无模型、零标注、纯几何，实现简单。
- 正面拍摄（竖线倾角 <6°）时可工作。

**缺点**：
- **固定角度带是硬伤**：斜拍时竖线偏离竖直 7–17°（本图左 17°/右 7.6°），超出容差（Python `tol_deg=15°`、Kotlin `V_BAND 0–6°`），竖线被当作斜向噪声丢弃。
- 对光照、模糊、棋盘倾斜敏感，阈值需逐场景调。

---

## ③ 透视无关直线聚类（方向 1 探索）

**原理**：放宽角度带 → `HoughLinesP` 线段 → 投影到中心列/行 → 聚类 → 投影网格 RANSAC 拟合「10 横 9 竖」规则网格。

**真机结果**：HoughLinesP 能检出斜竖线（285 线段），但重建网格失败，误差 ~109px。

**优点**：
- 解决「斜竖线检不出」的问题（线段检测比峰值投票鲁棒）。
- 方向正确：透视斜线可用线段处理。

**缺点**：
- **背景直线污染**：桌沿等背景直线混入候选，min/max 取极值选错外框。
- **网格重建不稳**：候选线太噪声，投影网格 RANSAC 无法稳定锁定规则网格。
- 需要堆大量 ROI/几何约束调参，换个光照角度又崩，性价比低。

---

## ④ 亮度/颜色分割

**原理**：本图棋盘是亮暖色（BGR 均值 ≈171/190/197），背景明显更暗（全图均值 108/112/113），用亮度阈值分割找最大连通域，再拟合四边形。

**真机结果**：亮区占 40% 但 `approxPolyDP` 得到 8–10 顶点，不成干净四边形。

**优点**：
- 实现极简，无模型。

**缺点**：
- 其它亮物体（棋子、手、白纸等）会与棋盘连通或竞争。
- 透视 + 形状不规则，难以稳定得到 4 顶点。
- 对光照/背景不鲁棒。

---

## ⑤ SAM 分割粗定位（方向 A）✓

**原理**：SAM（ViT-B）点提示（棋盘中心）分割出棋盘掩码 → 取最大轮廓 → `approxPolyDP` 拟合四角。

**真机结果**：

```
SAM 四角: [116,76] [350,76] [375,299] [102,306]
真实角点: [116,77] [346,72] [376,297] [96,306]
角点误差 ~3–4px（mask score 0.979，面积占比 19.4%）
```

**优点**：
- **零样本**（SA-1B 预训练），对斜拍、杂乱背景、光照都鲁棒，无需重训。
- 精度最高（~3–4px），分割掩码稳定。

**缺点**：
- **模型大、慢**：ViT-B 375MB，CPU 单帧 ~7s，不适合端上实时。
- 掩码给的是「物理棋盘边」，与「最外层网格线交点」有约 25px（canonical）系统偏移，需统一坐标定义。

**落地方式**：端上用 MobileSAM / EdgeSAM（~40MB、快）替换 ViT-B；提示策略可用中心点（假设棋盘近画面中心）或自动掩码 + 最大连通域。

## ⑥ SAM + 几何精修（方向 B 探索）

**原理**：SAM 粗定位 → `refine_corners`（`tools/label_real/refine.py`）rectify → 直线检测 → 匹配 canonical 网格节点 → 单应迭代精修。

**真机结果**：refine 内部收敛良好（`grid_rms=1.92px`、匹配 81 个网格节点），但输出的角点**内缩**（33px 误差）。

**优点**：
- 理论上可到亚像素。
- 有客观质量分（grid_rms / n_nodes / ortho / aspect）。

**缺点**：
- **坐标定义偏移**：refine 匹配的是内部网格线（canonical 留 25px 边框），而 SAM/人工标注是物理棋盘边，两者未对齐，导致角点内缩。
- 依赖好初值，初值差时发散。

**修复方向**：统一「物理边 ↔ 网格线交点」的坐标映射，或让 refine 输出物理边四角。

---

## 结论

1. **方向 A（SAM 轻量分割）** 是当前唯一稳定可用的定位方案，先做快速落地打通链路。
2. **方向 B（重训角点模型）** 作为后续优化：用 SAM 给真实/视频数据打伪标签，重训小角点模型，兼顾精度与端上速度。
3. 两个方向都要先解决「物理棋盘边 ↔ 网格线交点」的坐标定义统一问题。
