## 1. 项目概述

### 1.1 项目背景
本项目是 `face_recognition` 应用的核心功能验证版，完全基于 Android 手机实现，不依赖 AR 眼镜硬件。通过利用手机完备的摄像头与算力，在手机端完成「视频流采集 → 人脸识别 → 信息比对 → 结果显示」的完整闭环，为后续眼镜端方案验证核心逻辑、算法与数据流。

### 1.2 设计初衷
- 利用 Android 手机的成熟摄像头、算力与显示能力，快速验证核心功能。
- 不依赖 AR 眼镜及 Rokid SDK，降低开发与调试门槛。
- 与 `face_recognition`（眼镜版）共享人脸识别与信息比对逻辑，便于后续迁移。
- 先在手机端跑通完整闭环，再平滑移植到眼镜端。

### 1.3 与眼镜版的关系
| 维度 | face_recognition（眼镜版） | 本应用（手机版） |
| :--- | :--- | :--- |
| 采集端 | Rokid Glasses 摄像头 | Android 手机摄像头 |
| 算力端 | 手机（外置算力） | 手机（本地算力） |
| 显示端 | 眼镜镜片（绿色 UI） | 手机屏幕 |
| 传输 | BLE 传输图片 | 无需跨设备传输 |
| 目的 | 最终产品形态 | 核心功能验证 |

### 1.4 核心需求
| 需求项 | 说明 |
| :--- | :--- |
| **视频流采集** | 通过 Android 手机摄像头实时采集画面 |
| **人脸识别** | 运行人脸识别模型，输出 BBox 与标签 |
| **信息比对** | 将人脸信息与数据库比对，获取对应信息 |
| **结果显示** | 在手机屏幕上叠加显示 BBox 与对应信息 |
| **可验证性** | 作为眼镜版核心功能的验证平台 |

## 2. 系统架构

### 2.1 总体架构

```
┌───────────────────────────────────────────────┐
│              Android 手机 App                  │
│  ┌─────────────────────────────────────────┐  │
│  │  CameraX / Camera2  视频流采集           │  │
│  └─────────────────────────────────────────┘  │
│                    ↓ 视频帧                    │
│  ┌─────────────────────────────────────────┐  │
│  │  人脸识别模块（检测 → 特征提取）         │  │
│  └─────────────────────────────────────────┘  │
│                    ↓ 人脸特征                  │
│  ┌─────────────────────────────────────────┐  │
│  │  信息比对模块（查询数据库）              │  │
│  └─────────────────────────────────────────┘  │
│                    ↓ 对应信息                  │
│  ┌─────────────────────────────────────────┐  │
│  │  叠加渲染（BBox + 信息）                 │  │
│  └─────────────────────────────────────────┘  │
└───────────────────────────────────────────────┘
```

### 2.2 数据流

```
1. 手机摄像头采集视频帧
2. 人脸识别模块对视频帧进行检测，输出 BBox
3. 提取人脸特征，与数据库比对，获取对应信息
4. 在屏幕上叠加渲染 BBox 与对应信息
5. 循环执行 1-4，形成实时识别
```

## 3. 技术选型

### 3.1 摄像头采集
| 方案 | 优点 | 缺点 | 选择 |
| :--- | :--- | :--- | :--- |
| **CameraX** | 官方推荐、生命周期感知、易用 | 对底层控制较弱 | **首选** |
| Camera2 | 控制精细、性能好 | 使用复杂 | 备选 |

### 3.2 人脸检测与识别方案（核心约束：运行时零 Google Play 依赖）
> 国内手机普遍无 Google Play（GMS），因此**必须离线本地推理**：模型打包进 APK，运行时零 GMS 依赖。

| 方案 | 优点 | 缺点 | 选择 |
| :--- | :--- | :--- | :--- |
| **MediaPipe FaceDetector** | 轻量（~230KB）、实时、离线、无需训练 | 仅检测 BBox + 6 关键点 | **首选（检测）** |
| **MediaPipe FaceEmbedder** | 离线、输出 192 维特征、无需训练 | 模型 ~3.8MB 需打包 | **首选（识别）** |
| **TFLite + 开源权重**（RetinaFace / MobileFaceNet 等） | 可完全替换、灵活 | 需自己写推理/转换 | 后续替换用 |
| ~~ML Kit（play-services 版）~~ | —— | **依赖 GMS，国内不可用** | ❌ 弃用 |

> MediaPipe Tasks 为纯本地推理：`tasks-vision` 依赖与 `.tflite` 模型均离线，运行时无 GMS。

### 3.3 信息比对与数据库
| 方案 | 优点 | 缺点 | 选择 |
| :--- | :--- | :--- | :--- |
| **本地特征库 + 余弦相似度** | 离线、简单、无需后端 | 规模受限 | **首选** |
| 本地 SQLite | 持久化、可扩展 | 稍复杂 | 第三阶段引入 |
| 服务端数据库 | 规模大 | 需网络与后端，国内部署成本高 | 备选 |

> 比对算法：特征向量归一化后计算余弦相似度，超过阈值即判定同一人。

### 3.4 开发环境
- **IDE**：Android Studio
- **语言**：Kotlin
- **minSdk**：24 (Android 7+)
- **核心依赖**：CameraX 1.6.0、MediaPipe `tasks-vision` 0.10.35

### 3.5 模型可替换架构（接口隔离）

```
UI 层（MainActivity + OverlayView）
        │ 只依赖接口
引擎层：FaceDetector / FaceRecognizer 接口 + FaceEngine 工厂
        ├── MediaPipe 实现（现成库，快速验证）
        └── TFLite 实现（后续替换开源权重）
数据层：特征库 + 余弦相似度比对
```

- 定义与模型无关的 `FaceBox` 数据类、`FaceDetector` / `FaceRecognizer` 接口。
- `FaceEngine` 工厂按配置返回具体实现，换模型只改工厂，不动调用方。
- 模型文件统一放 `assets/models/`，随 APK 打包、运行时本地加载。

## 4. 详细工作流

### 4.1 第一阶段：环境搭建
1. 新建 Android 项目，集成 CameraX。
2. 接入人脸识别模型依赖。
3. 实现摄像头预览与视频帧回调。

### 4.2 第二阶段：人脸检测
```kotlin
// 示例：视频帧回调中执行检测
override fun analyze(imageProxy: ImageProxy) {
    val bitmap = imageProxy.toBitmap()
    val faces = faceDetector.detect(bitmap)  // 输出 BBox 列表
    imageProxy.close()
}
```

### 4.3 第三阶段：信息比对
```kotlin
// 示例：提取特征并与数据库比对
val feature = extractFeature(faceCrop)
val info = database.match(feature)  // 返回对应信息或 null
```

### 4.4 第四阶段：叠加显示
- 在预览层上叠加自定义 View，绘制 BBox 框。
- 在 BBox 下方绘制对应信息文字。

### 4.5 第五阶段：优化与验证
- 控制识别频率，避免过高 CPU 占用。
- 对比不同模型的延迟与准确率。
- 验证比对准确性，为眼镜版迁移做准备。

## 5. 关键实现细节

### 5.1 性能指标
| 环节 | 目标 |
| :--- | :--- |
| 视频帧采集 | 15-30 fps |
| 人脸检测延迟 | < 100ms |
| 完整闭环延迟 | < 200ms |
| 内存占用 | 复用 Bitmap，避免 OOM |

### 5.2 内存管理
- 视频帧及时回收，使用 `inBitmap` 复用。
- 检测结果按帧更新，不累积历史数据。

## 6. 与眼镜版的差异

| 项目 | 手机版 | 眼镜版 |
| :--- | :--- | :--- |
| 视频流来源 | 手机摄像头 | 眼镜摄像头（BLE 传输） |
| 显示方式 | 手机屏幕彩色渲染 | 眼镜镜片单色绿渲染 |
| 坐标映射 | 无需映射 | 需 `getAlignmentRect` 映射 |
| 通信 | 本地直接处理 | 跨设备 BLE 传输 |
| 核心逻辑（人脸识别、信息比对） | 一致 | 一致 |
