## 2026-10-01：阶段总结 — v1.0.0 里程碑（告一段落）

本阶段「功能跑通」目标达成，交付 **v1.0.0**（versionName 1.0.0 / versionCode 1）。

### 已完成功能
| 模块 | 说明 |
|:--|:--|
| 摄像头预览 | CameraX 1.6.0 实时预览 + ImageAnalysis 帧回调（fps≈30） |
| 人脸检测 | MediaPipe FaceDetector（blaze_face_short_range，阈值 0.6）+ EMA/IoU 时间平滑 + 确认/丢失迟滞 |
| 人脸识别 | MobileFaceNet TFLite（112×112，128 维，NCHW）+ 双眼关键点相似变换对齐 + 余弦相似度（阈值 0.4） |
| 特征库 | SharedPreferences 持久化（key=`face_<名字>`），重启后可识别 |
| 前后摄像头切换 | 「切换」按钮 + 前置镜像对齐 + `hasCamera` 防黑屏 |
| 识别 UI | 绿色 BBox + 名字/相似度标签 + 龙珠风格「战斗力：xxx」字幕（0~10000，随轨迹稳定） |
| 框对齐 | 按 PreviewView FILL_CENTER 缩放+裁剪映射归一化坐标 |

### 关键架构决策
- **不依赖 GMS**：纯本地离线推理（MediaPipe + TFLite），适配国内无 GMS 真机。
- **预留替换接口**：`FaceDetector`/`FaceRecognizer`（嵌入）接口 + `FaceEngine` 工厂，后续换开源权重只加实现、改工厂一行。
- **tasks-vision 0.10.35 无 FaceEmbedder**（已解包 AAR 确认），故识别改 TFLite + MobileFaceNet 直接推理。

### 真机安装包
- 临时加 `ndk { abiFilters += "arm64-v8a" }` 生成 arm64-only 精简包：`face_recognition_phone_version_v1.0.0.apk`（约 27MB，对比全 ABI 约 70+MB）。
- 生成后已回退该行，保持全 ABI 以便模拟器调试。

### 遗留问题 / 下一步
1. **模型效果不理想**（同一人相似度偏低、不同人有重叠），待用户重选识别模型后替换。
2. 短距离检测模型固有局限：人脸过近/出画时偶发丢失，可评估换 `blaze_face_full_range` 或做多帧插值。

## 2026-10-01：识别误配修复 — 人脸关键点对齐

### 问题
用户反馈「画面中多个不同的人脸被识别为同一个注册名字」。日志显示同一注册人（"0702"）对多张脸相似度仅 0.45~0.56，同一人相似度偏低、不同人又重叠在 0.4 阈值之上。

### 根因
此前只做简单方形裁剪（框中心 + padding），**没有人脸对齐**。对照 Qualcomm 官方 demo（`demo.py`/`app.py`）：官方用 RetinaFace + 5 点关键点 `warp_and_crop_face`（`inner_padding_factor=0.25`）对齐后再嵌入，相似度用余弦角（阈值 70°）。缺少对齐导致特征判别力下降，不同人脸混淆。

### 修复
用 MediaPipe 6 关键点中的双眼做相似变换（旋转 + 缩放 + 平移），映射到 112×112 标准位置（InsightFace/RetinaFace 5 点模板）。

| 文件 | 改动 |
|:--|:--|
| `face/FaceBox.kt` | 加 `keypoints` 字段（归一化 `[0,1]` 关键点） |
| `face/MediaPipeFaceDetector.kt` | 提取 `detection.keypoints()`（0=右眼 1=左眼 2=鼻尖 3=嘴中心 4/5=耳） |
| `face/FaceBoxSmoother.kt` | `blend()` 同步线性插值关键点 |
| `MainActivity.kt` | 新增 `alignByEyes()`（相似变换到 112×112）与 `alignFace()`（无关键点回退 `cropFace`）；识别与注册均改用 `alignFace()` |
| `face/FaceDatabase.kt` | 加 `topSimilarity()` 诊断（未命中也输出最高相似度） |

对齐矩阵：`preTranslate(EYE_LEFT) → preScale(s) → preRotate(θ) → preTranslate(-eye0)`，θ = 源眼向角 − 目标眼向角；双眼按 x 排序保证左右一一对应。目标模板：左眼 (30.29, 51.70)、右眼 (65.53, 51.50)，眼距 ≈ 35.24。

### 状态
编译/构建/安装成功，无崩溃。识别日志新增 `topSim` 字段（`recognition: <名字|未匹配> (topSim=0.xxx)`），待用户实操验证：同一人相似度应升至 0.6+，不同人应低于 0.4 阈值。

## 2026-10-01：第三阶段 — 特征提取 + 本地比对 + 注册识别

### 关键发现（修正设计文档假设）
`tasks-vision 0.10.35` 里**没有 `FaceEmbedder`**（解包 AAR 确认，仅 FaceDetector / FaceLandmarker / ImageEmbedder）。设计文档假设的「MediaPipe FaceEmbedder（192 维）」不成立。改为 **TFLite + MobileFaceNet** 直接推理，契合「后续替换开源权重」的诉求。

### 技术选型
| 项 | 值 |
|:--|:--|
| 识别模型 | MobileFaceNet TFLite（112×112 输入，**128 维**输出，约 4MB） |
| 来源 | Qualcomm AI Hub（`mobile_facenet.tflite`） |
| 推理 | `org.tensorflow:tensorflow-lite:2.16.1` 直接跑，纯离线 |
| 输入格式 | **NCHW** `[1,3,112,112]` float32 [0,1]（ImageNet 归一化内置于图） |
| 模型结构 | 双输入（img1/img2，人脸比对结构），喂同一张脸取第一个输出 |
| 比对 | 特征 L2 归一化 → 余弦相似度，阈值 0.4 |
| 对齐 | 简单方形裁剪（框中心 + padding），完整人脸对齐后续再做 |

### 改动清单
| 文件 | 改动 |
|:--|:--|
| `assets/models/mobile_facenet.tflite` | 下载识别模型（3.99MB） |
| `libs.versions.toml` / `build.gradle.kts` | 加 `tensorflow-lite` 依赖 |
| `face/FaceEmbedder.kt` | 特征提取接口 |
| `face/TfliteFaceEmbedder.kt` | TFLite 实现（NCHW 预处理 + L2 归一化） |
| `face/FaceDatabase.kt` | 内存特征库 + 余弦相似度匹配 |
| `face/FaceEngine.kt` | 加 `createEmbedder()` |
| `overlay/FaceOverlayView.kt` | 加名字/相似度文字绘制 |
| `activity_main.xml` | 加「注册」按钮 |
| `MainActivity.kt` | 集成：检测→裁剪→嵌入→匹配→显示；注册流程（按钮→命名→录入）；识别节流（每 3 帧） |

### 遇到的问题与解决
1. **双输入模型 `run()` 报错**：`DataType error: cannot resolve DataType of [Ljava.lang.Object`。原因是双输入模型必须用 `runForMultipleInputsOutputs(Object[], Map<Integer,Object>)`，`run(Object,Object)` 会把输入数组当单张量。已修复。
2. **TFLite 无 GMS**：`libtensorflowlite_jni_gms_client.so not found` 属正常，自动回退本地 `libtensorflowlite_jni.so`。

### 状态
构建/安装成功，TFLite 模型加载正常，无崩溃；识别 pipeline 待用户实操验证（注册→识别）。

## 2026-10-01：第二阶段 — MediaPipe 检测 + 框抖动修复

### 目标
接入 MediaPipe 人脸检测，实时画框；解决框大小不停变化导致的闪烁。

### 改动清单
| 文件 | 改动 |
|:--|:--|
| `gradle/libs.versions.toml` | 加 `mediapipe = "0.10.35"`，依赖 `tasks-vision` |
| `app/build.gradle.kts` | 引用 MediaPipe 依赖 |
| `assets/models/blaze_face_short_range.tflite` | 下载检测模型（224KB） |
| `face/FaceBox.kt` | 归一化 `[0,1]` 检测结果 |
| `face/FaceDetector.kt` | 检测接口 |
| `face/MediaPipeFaceDetector.kt` | MediaPipe 实现（RunningMode.IMAGE） |
| `face/FaceEngine.kt` | 工厂，`createDetector()` |
| `face/FaceBoxSmoother.kt` | 新增：EMA 时间平滑 + IoU 轨迹匹配 |
| `overlay/FaceOverlayView.kt` | 叠加层，画绿色 BBox |
| `activity_main.xml` / `MainActivity.kt` | 接检测 + 平滑 + 诊断日志 |

### 遇到的问题与解决
1. **源文件写错路径**：4 个 Kotlin 文件误写到工程根目录 `face/`，用 `mv` 移到 `app/src/main/java/...` 下。
2. **框闪烁（核心问题）**：检测结果逐帧抖动、无时间平滑。诊断日志量化出 `rawJitter`（平滑前）与 `smoothJitter`（平滑后），确认是高频抖动。用 `FaceBoxSmoother` 做 EMA（α=0.35）+ IoU 匹配，稳定后逐帧抖动降约 50%（如 0.0086→0.0030）。

### 诊断日志说明
`MainActivity` 每秒输出一行：`fps`、`avgDetect`、`rawJitter`（平滑前逐帧最大位移）、`smoothJitter`（平滑后）、`box` 坐标。TAG = `FaceRecognition`。

### 待处理
- 预览与检测位图宽高比不一致，框可能存在轻微不对齐（单独问题，非闪烁）。
- 真实人脸离镜头太近/部分出画时（框 `r>1.0`、score 贴 0.6），检测会偶发丢失；属短距离模型固有限制，后续可评估换 `blaze_face_full_range` 或做多帧插值。

### 误检修复（追加）
用户反馈「不是人脸的地方检出人脸」。原因：`minDetectionConfidence=0.5` 过低 + 无时序稳定性过滤。

改动：
1. `MediaPipeFaceDetector` 阈值 `0.5 → 0.6`（常量 `MIN_DETECTION_CONFIDENCE`），过滤低分误检；
2. `FaceBoxSmoother` 增加**确认迟滞**（连续 `confirmFrames=3` 帧才输出）与**丢失迟滞**（消失 `maxLostFrames=5` 帧内仍保留），抑制偶发误检与跳变。

日志验证：`raw`（原始检测数）稳定 ≤1，原 score≈0.54 的误检第二人脸不再出现。

3. **预留模型替换接口**：定义 `FaceDetector` / `FaceRecognizer` 接口 + `FaceEngine` 工厂，后续换开源权重（TFLite）只加实现、改工厂一行。
