# 基于 Rokid Glasses 的异步 AR 人脸识别标注系统 — 设计文档

**版本**：v1.0
**日期**：2026-09-29
**作者**：个人开发者
**状态**：设计阶段

---

## 1. 项目概述

### 1.1 项目背景
本项目旨在基于 Rokid Glasses 智能眼镜，构建一个“手机算力 + 眼镜显示”的异步 AR 应用。核心功能是：眼镜拍摄前方画面 → 手机端接收图片并进行人脸识别 → 将识别结果（边界框 BBox + 文字描述）以绿色 UI 形式推送到眼镜镜片上显示。

### 1.2 设计初衷
- 充分利用手机或电脑的算力，避免在眼镜端运行复杂 AI 模型。
- 不依赖 SLAM 建图或高精度位姿追踪，降低系统复杂度。
- 在当前 SDK 权限限制下，以“拍照模式”实现可用的异步 AR 闭环。
- 保持架构可演进性，未来可平滑升级至连续视频流方案。

### 1.3 核心需求
| 需求项 | 说明 |
| :--- | :--- |
| **图像采集** | 通过 Rokid Glasses 摄像头获取第一视角画面 |
| **人脸识别** | 在手机端对采集图像进行人脸检测，输出 BBox 与文字标签 |
| **眼镜显示** | 将 BBox 和文字以绿色 UI 形式叠加到眼镜镜片上 |
| **外置算力** | 所有 AI 计算在手机端完成，眼镜仅负责采集与显示 |
| **个人可开发** | 基于社区可获取的 SDK，不依赖商务合作权限 |
| **近视适配** | 支持佩戴者近视矫正，不影响使用 |

## 2. 硬件平台选型

### 2.1 选定设备：Rokid Glasses

| 特性 | 规格 | 对本项目的意义 |
| :--- | :--- | :--- |
| **摄像头** | 1200 万像素 Sony IMX681，FOV 109° | 提供第一视角图像采集能力 |
| **显示** | 双目单色绿色 Micro-LED，480×398，1500 尼特 | 满足绿色 UI 渲染，户外可见 |
| **IMU** | 支持 3DoF/6DoF 追踪 | 可用于未来姿态辅助，当前阶段非必需 |
| **麦克风** | 4 颗定向拾音阵列 | 未来可扩展语音交互 |
| **连接** | 蓝牙 5.3 + Wi-Fi 6，USB-C 仅充电/ADB | 数据主要通过无线传输 |
| **续航** | 高强度使用约 45 分钟 - 2 小时 | 需搭配外接电源（Power Capsule） |
| **重量** | 约 49g | 适合长时间佩戴 |
| **近视支持** | 磁吸处方镜片框架，$39，支持 400 度 | 已确认可配镜 |

### 2.2 为什么不是其他设备
- **Rokid Max 2 / XREAL One**：虽支持高带宽有线视频输入，但无摄像头，无法采集第一视角画面。
- **INMO Air3**：开放度较高，但一体机设计更偏向独立运行，且 SDK 对视频流支持不明确。
- **千问 AI 眼镜**：封闭的消费级 AI 助手，不提供底层传感器数据接口。

**结论**：Rokid Glasses 是目前在“带摄像头 + 可开发 + 近视支持 + 个人可负担”四个条件下最匹配的选择。

## 3. 系统架构

### 3.1 总体架构图

```
┌─────────────────────────────────────────────────────────────┐
│                      手机端 App (Android)                    │
│  ┌───────────────────────────────────────────────────────┐  │
│  │  CXR-L SDK (client-l:1.0.3)                           │  │
│  │  • 连接管理  • 远程拍照  • Custom View 推送            │  │
│  └───────────────────────────────────────────────────────┘  │
│                            ↕ 授权 Token                      │
│  ┌───────────────────────────────────────────────────────┐  │
│  │  Rokid AI App (≥1.7.14)                               │  │
│  │  仅用于 OAuth 授权，完成后退出，不参与数据流            │  │
│  └───────────────────────────────────────────────────────┘  │
│                            ↕ BLE / 自定义协议                │
│  ┌───────────────────────────────────────────────────────┐  │
│  │              Rokid Glasses (眼镜端)                     │  │
│  │  • 摄像头采集  • ISP 压缩  • 显示绿色 UI               │  │
│  └───────────────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────────────┘
```

### 3.2 数据流

```
1. 手机 App 发起拍照请求
2. 眼镜摄像头采集 → ISP 压缩为 WebP → BLE 分包传输
3. 手机 App 接收 WebP 字节流 → 解码为 Bitmap
4. 手机端运行人脸识别模型 → 输出 BBox + 标签
5. 坐标映射 (getAlignmentRect) → 生成绿色 JSON UI
6. 通过 Custom View 推送到眼镜
7. 眼镜渲染绿色 BBox + 文字
8. 循环执行 1-7，形成异步快照更新
```

## 4. 技术选型

### 4.1 SDK 选择：CXR-L

| 候选 SDK | 视频流 | 拍照 | UI 推送 | IMU | 社区可获取 | 结论 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **CXR-M** | ✅ 1080P@30fps | ✅ | ✅ | ❌ | ❌ 仅商务合作 | 不可用 |
| **CXR-L** | ❌ | ✅ 单张 WebP | ✅ | ❌ | ✅ | **本项目选用** |
| **CXR-S (裸机)** | ❌ | ✅ | 眼镜端原生 | 有限 | ✅ | 备选，复杂度高 |
| **3DOF/6DOF SDK** | ❌ | ❌ | ❌ | ✅ 融合数据 | 有条件 | 未来姿态辅助 |

**最终选择**：CXR-L SDK，以拍照模式实现异步 AR 闭环。

### 4.2 人脸识别方案

| 方案 | 优点 | 缺点 | 选择 |
| :--- | :--- | :--- | :--- |
| **MediaPipe Face Detection** | 轻量、实时、无需训练、API 简单 | 仅检测，不识别身份 | **首选** |
| **RokidFaceSDK** | 检测+跟踪+识别一体，准确率 99.8% | 需额外集成，可能依赖商务权限 | 备选 |

## 5. 详细工作流

### 5.1 第一阶段：环境搭建与 SDK 集成

**步骤**：
1. 新建 Android 项目，配置 Gradle 仓库。
2. 添加依赖 `client-l:1.0.3`。
3. 确保手机安装 Rokid AI App ≥ 1.7.14。
4. 参考 `RenewCXRLSample` 搭建基础框架。

### 5.2 第二阶段：认证与会话建立

**核心代码逻辑**：

```kotlin
val link = CXRLink(context)
link.configCXRSession(SessionType.CUSTOMVIEW)
link.setLinkCallback(object : LinkCallback {
    override fun onCXRLConnected(connected: Boolean) { /* 链路就绪 */ }
    override fun onGlassBtConnected(connected: Boolean) { /* 蓝牙就绪 */ }
})
link.connect(token)  // token 来自 Rokid AI App 授权
```

**关键点**：
- 必须等待 `onCustomViewOpened` 回调触发，才表示场景构建完成，拍照能力解锁。
- 在场景就绪前调用拍照会返回 `FAILED`。

### 5.3 第三阶段：拍照与人脸识别

**相机管理**：
```kotlin
// 建议显式打开相机
CxrApi.getInstance().openGlassCamera(1280, 720, 85)
```
- **30 秒自动下电**：30 秒无拍照需重新 `openGlassCamera()`。
- **推荐分辨率**：1280×720，quality 85（延迟与画质最佳平衡）。

**触发拍照**：
```kotlin
CxrApi.getInstance().takeGlassPhoto(1280, 720, 85, callback)
```
- 底层耗时约 **220ms**（空口 160ms + ISP 压缩 38ms + 协议头 22ms）。

**接收与识别**：
```kotlin
override fun onPhotoResult(status: CxrStatus?, photo: ByteArray?) {
    if (status == CxrStatus.RESPONSE_SUCCEED) {
        val bitmap = BitmapFactory.decodeByteArray(photo, 0, photo.size)
        val faces = faceDetector.detect(bitmap)
        bitmap.recycle()  // 立即回收
    }
}
```
- **内存管理**：720p WebP 约 120KB，解码后约 3.5MB，必须复用 `inBitmap` 防止 OOM。

### 5.4 第四阶段：坐标映射与 UI 推送

**坐标映射**：
```kotlin
val rect = RokidSystem.getAlignmentRect(1280, 720, face.boundingBox)
```
- 将摄像头预览帧坐标映射到眼镜 LCD 实际显示区域。

**构建绿色 UI**：
```kotlin
val json = """
{
  "type": "RelativeLayout",
  "props": { "layout_width": "match_parent", "layout_height": "match_parent" },
  "children": [
    {
      "type": "Rect",
      "props": {
        "left": ${rect.left}, "top": ${rect.top},
        "right": ${rect.right}, "bottom": ${rect.bottom},
        "strokeColor": "#00FF00", "strokeWidth": 3
      }
    },
    {
      "type": "Text",
      "props": {
        "text": "Face 1", "textColor": "#00FF00",
        "textSize": 16, "x": ${rect.left}, "y": ${rect.bottom + 10}
      }
    }
  ]
}
""".trimIndent()
```

**推送**：
```kotlin
CxrApi.getInstance().openCustomView(json)      // 首次
CxrApi.getInstance().updateCustomView(json)    // 增量更新
```

### 5.5 第五阶段：循环与优化

- **拍照间隔**：建议 ≥ 300ms（约 3Hz），避免 BLE 拥塞。
- **UI 更新节流**：仅当 BBox 位置变化超过阈值时才推送更新。
- **物理按键屏蔽**：`setKeyEventListener(false)` 防止拍照被抢占。
- **相机状态维护**：记录上次拍照时间，超 30 秒需重新 open。

## 6. 关键实现细节

### 6.1 显示约束
- **单色绿**：所有 UI 元素必须使用 `#00FF00`，否则显示为黑色。
- **支持布局**：LinearLayout、RelativeLayout、ConstraintLayout（居中约束）。
- **图标资源**：需先 `sendCustomViewIcons()` 异步上传，等待 `onIconsSent()` 后再打开界面。

### 6.2 性能数据

| 环节 | 耗时/频率 |
| :--- | :--- |
| 拍照端到端延迟 | 约 220ms |
| 完整闭环（拍照→识别→显示） | 约 300-500ms |
| 建议更新频率 | 2-3 Hz |
| 视频流模式对比（CXR-M） | 30 Hz，延迟 <500ms |

### 6.3 错误处理

| 错误状态 | 原因 | 处理 |
| :--- | :--- | :--- |
| `RESPONSE_TIMEOUT` | BLE 被物理按键抢占 | 屏蔽按键，重试一次 |
| `RESPONSE_INVALID` | 硬件故障或相机未打开 | 检查 `openGlassCamera` |
| 图标不显示 | 未先上传图标资源 | 调用 `sendCustomViewIcons` 并等待回调 |

### 6.4 电源与散热
- **续航**：高强度使用约 45 分钟 - 2 小时。
- **外接电源**：Rokid Power Capsule（1800mAh）磁吸边充边用。
- **发热**：边充边用会加剧发热，建议优化应用逻辑降低持续负载。
- **物理散热**：固定工位可加小风扇或散热贴。

## 7. 限制与风险

| 限制 | 影响 | 缓解措施 |
| :--- | :--- | :--- |
| **无连续视频流** | 更新频率仅 2-3Hz，标注跳跃式 | 接受异步体验，优化节流逻辑 |
| **无原始 IMU 数据** | 无法做高精度姿态辅助 | 当前阶段非必需；未来探索 3DOF/6DOF SDK 或第三方驱动 |
| **CXR-M 不开放** | 无法实现实时 AR | 以 CXR-L 拍照模式验证核心逻辑，等待权限开放 |
| **单色绿显示** | 无法呈现彩色虚拟物体 | 所有 UI 使用绿色，信息通过形状和文字区分 |
| **续航有限** | 高强度使用 <2 小时 | 搭配 Power Capsule，优化采集频率 |
| **发热** | 边充边用温度升高 | 间歇性采集，物理散热 |
| **射频干扰** | BLE/Wi-Fi 共存时丢包 | 测试时关闭 Wi-Fi，仅用 BLE |

## 9. 备选方案

### 9.1 硬件备选：INMO Air3
- **优势**：Unity SDK + Open API，对开发者更开放，可能支持视频流。
- **劣势**：一体机设计，算力有限，需验证视频流接口。
- **适用**：如果视频流实时性是硬性要求，可评估切换硬件。

### 9.2 SDK 备选：xg.glass SDK
- **优势**：跨平台统一 API，抽象了 Rokid 等厂商的专有 SDK。
- **限制**：对 Rokid Glasses 的视频流支持目前标记为“No”，但拍照和音频支持。
- **适用**：作为统一抽象层，简化多设备适配。

### 9.3 未来升级：CXR-M 权限开放
- 若未来获得 CXR-M 商务合作权限，可平滑升级至 1080P@30fps 实时视频流，更新频率提升至 30Hz，实现真正的实时 AR 追踪。

## 11. 待解决问题

1. **CXR-L 对 Rokid Glasses 的兼容性**：需实际验证 `client-l:1.0.3` 是否完全支持当前眼镜固件。
2. **人脸识别模型选择**：MediaPipe 在手机端的实际推理延迟需测试。
3. **坐标映射精度**：`getAlignmentRect` 在不同佩戴角度下的映射误差需评估。
4. **长时间运行稳定性**：BLE 连接在 30 分钟以上是否稳定，发热是否触发降频。
5. **外接电源方案**：Power Capsule 是否支持边充边用，发热是否可接受。
