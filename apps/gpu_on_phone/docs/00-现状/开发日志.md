## 2026-10-14 晚 外部调研完成（GitHub + arXiv 四路并行检索）

- **产出**：`03-探索与调研/GPU加速调研汇总（GitHub与arXiv）.md`（全量结果：11 个推理引擎横评、厂商 SDK、SAM/YOLO 端侧先例、40+ 篇 arXiv 论文、公开加速比数据表）；`GPU加速候选路线.md` 修订为决策跟踪版。设计文档 §3/§6/§8 同步。
- **三条硬结论**：
  1. **V2509A = vivo X300 = 天玑 9500（MT6990）/ Mali-G1-Ultra**（三源印证）→ D QNN、B NNAPI 路线关闭；**MT6990 在 LiteRT MediaTek NPU 官方支持列表内** → 新增 C+ 上限路线。
  2. **ONNX Runtime Android 官方包无任何 GPU EP**（Java API 实测仅 NNAPI/XNNPACK/QNN/CUDA）→「ORT 内换 EP 上 GPU」不通；ORT 1.22→1.31（2026-10-09 发布）升级有免费 CPU 红利。
  3. **EdgeSAM 模型侧不过时**：iPhone 14 全流程 38.7 FPS（CoreML/ANE）vs 我们 ORT CPU ~1s = 40× 差距在推理栈；**encoder（RepViT-M1）是纯 CNN**（纠正此前「ViT」的误判）→ LiteRT GPU delegate 算子覆盖良好；decoder（transformer）留 CPU（社区实测 <100ms）。
- **其他要点**：SAM×Android×GPU 是公开空白区（社区先例全停更，官方无 Android demo）；预期锚点 GPU 2–6× / NPU 20–45×，但小模型 GPU 可能负优化（ncnn 作者警示 + iPhone LLM 0.75× 实证）；量化方法论现成（PTQ4SAM/SAQ-SAM/Q-TinySAM W8A8：-21.8% 延迟/-0.9 AP）；热节流方法论（Play It Cool：不控温的 A/B 无效）并入设计文档 §4；512 输入分辨率是可与 GPU 叠加的免费收益；EdgeSAM 上游 NTU S-Lab License 1.0（商用需审）。
- **路线修订**：A（CPU/XNNPACK+ORT 升级）保留先做｜B NNAPI ❌｜C LiteRT GPU ✅ 主线｜C+ LiteRT MTK NPU ✅ 新增（G2）｜D QNN ❌｜E ncnn/MNN 备选｜F 原生降权。
- **下一步（G0，不变+两点补充）**：① 真机 getprop 复核 SoC/Android 版本；② benchmark App 骨架；③ 模型拷入；④ A 基线（含 ORT 1.31 升级）；⑤ 顺带调研 PyTorch 上游→tflite 导出链路（C 路线前置）。
